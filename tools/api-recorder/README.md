# Рекордер відповідей API банків

Скрипт для власника: записує справжні відповіді трьох API на ваших рахунках, щоб конектори платформи
завантаження виписок (етап 5а) перевірялись на реальних даних, а не на припущеннях з документації.

* ПриватБанк — «Автоклієнт» (`acp.privatbank.ua`);
* monobank для юросіб — corp-api (`corp-api.monobank.ua`);
* monobank ФОП — персональне API (`api.monobank.ua`).

**У банку скрипт лише читає.** Жодних платежів, вебхуків, змін налаштувань. Це забезпечено в коді, а не обіцянкою:
дозволені лише `GET` і лише шляхи читання з білого списку (`ApiRecorder.Lib.ps1`); будь-що інше скрипт відмовляється
надсилати. Запити, які могли б щось змінити, у скрипті відсутні.

Файли поруч:

| Файл | Що |
|---|---|
| `Invoke-ApiRecorder.ps1` | Сам рекордер (+ режими `-DryRun` і `-SelfTest`). |
| `ApiRecorder.Lib.ps1` | Спільні функції: білі списки, запис обмінів, пошук токенів. |
| `config.template.psd1` | Шаблон конфігурації із заглушками (єдине, що лежить у git). |
| `FORMAT.md` | Опис формату запису (для знеособлювача й транспорту відтворення). |

## Де що лежить і чому

| Що | Де | Чому там |
|---|---|---|
| Код, шаблон, README, формат | `tools/api-recorder/` у git | це інструмент, він публічний |
| **Ваша конфігурація з токенами** | `R:\github\SMP_BankExchange\temp\api-recorder\config.psd1` | `temp/` гітігнорована; файл читаєте тільки ви |
| **Записи** | `R:\github\SMP_BankExchange\temp\api-recordings\<банк>\<мітка прогону>\` | див. нижче |
| Суми й ідентифікатори для звірки | `…\api-recordings\_owner-only\` | лише вам |

Записи й конфігурація лежать в **основному дереві**, а не поряд зі скриптом, свідомо: записи — це ваша праця
(справжні відповіді банків, які неможливо відтворити за потреби), вони знадобляться й етапу 5б, а робоче дерево
(ворктрі) цього плану тимчасове й буде видалене після злиття. Шляхи можна змінити параметрами скрипта
(`-Config`, `-OutRoot`), але за замовчуванням — саме ці.

Чернетка конфігурації вже лежить на місці (копія шаблону із заглушками): лишається вписати значення.

## Що потрібно

* PowerShell 7.5 або новіший (`pwsh`). Нічого більше ставити не треба.
* Токени (див. нижче) і IBAN рахунків.
* Доступ до інтернету з тієї машини, з якої дозволено токен (для Автоклієнта в токена можуть бути IP-обмеження).

## Де взяти токени

| Банк | Що | Де |
|---|---|---|
| ПриватБанк | ідентифікатор і токен | Автоклієнт: підключіть застосунок «Інтеграція (Автоклієнт)», відкрийте налаштування створеного застосунку API, кнопка «ID i Token». Тариф: для юросіб «Бізнес Комфорт» або «Бізнес ПРО», для ФОП — будь-який. Якщо обмежуєте сервіси API — залиште доступними виписки (баланси й транзакції). |
| monobank юросіб | токен | web.monobank.ua, вхід, обрати компанію, «Токени» (`web.monobank.ua/?modal=tokens`), створити токен для персонального використання. |
| monobank ФОП | особистий токен | api.monobank.ua, «Отримати токен» (вхід через застосунок monobank). |

Біля кожного поля у `config.psd1` є коментар із цим самим і з очікуваним форматом.

## Що вписати

Відкрийте `R:\github\SMP_BankExchange\temp\api-recorder\config.psd1` і замініть заглушки `<ВПИШІТЬ_…>` (разом з
кутовими дужками) на значення в одинарних лапках. Для кожного банку:

* токен (і ідентифікатор для Привату), IBAN рахунків;
* **період** (`Period`): дві дати `РРРР-ММ-ДД` включно, до сьогоднішнього дня. Беріть період, де є кілька десятків
  операцій, а на якусь добу — більше, ніж розмір малої сторінки;
* за бажанням — **період зі скасуванням чи поверненням** (`ReversalPeriod`): період, у якому банк повертав або
  анулював операцію. Це вирішує, як платформа розуміє повернення. **Не пам'ятаєте — залиште заглушки:** сценарій
  буде пропущено, нічого вигадувати не треба;
* для monobank ФОП — за бажанням **насичений період** (`SaturatedPeriod`, найкраще кілька сотень операцій за 31 добу);
* у блоці `Scenarios` — які сценарії вмикати.

Банк, який вам не потрібен, вимкніть: `Enabled = $false`. Банк із незаповненою заглушкою рекордер **не запускає**:
пише, що саме не заповнено, і переходить до наступного (код виходу 2).

## Як запускати

З теки `tools/api-recorder` (в консолі `pwsh`):

```powershell
# 1. Перевірка самого рекордера, без мережі й без ваших токенів (займає секунди)
pwsh -NoProfile -File .\Invoke-ApiRecorder.ps1 -SelfTest

# 2. План запитів без мережі: що буде надіслано і скільки це триватиме
pwsh -NoProfile -File .\Invoke-ApiRecorder.ps1 -DryRun

# 3. Справжній прогін (один банк, щоб спробувати)
pwsh -NoProfile -File .\Invoke-ApiRecorder.ps1 -Bank privat

# 4. Усі ввімкнені банки
pwsh -NoProfile -File .\Invoke-ApiRecorder.ps1
```

`-Bank` приймає `privat`, `monoCorp`, `monoFop`, `all`. Інші параметри: `-RunLabel` (мітка прогону = назва теки,
за замовчуванням дата й час), `-Config`, `-OutRoot`.

**Скільки триває.** ПриватБанк і monobank юросіб — хвилини (пауза ~1 с між запитами). **monobank ФОП — повільний:**
банк дозволяє виписку не частіше ніж раз на 60 секунд, тож між запитами рекордер чекає 61 с; кілька відрізків
періоду плюс сценарії помилок — це десятки хвилин. Скільки саме, показує `-DryRun` (рядок «сумарні паузи»).
Прогін можна запускати на тлі й іншою роботою; не закривайте вікно.

## Що робить рекордер у банку

Лише `GET`. Повний перелік шляхів — білий список у коді; сенс і джерело кожного:

| Банк | Шлях | Для чого | Документація |
|---|---|---|---|
| ПриватБанк | `/api/statements/settings` | серверні дати, фаза, ознака регламенту | розділ «Отримання серверних дат» |
| | `/api/statements/balance` (також `/interim`, `/final`) | баланси | «Отримання балансів і транзакцій за рахунками» |
| | `/api/statements/transactions` (також `/interim`, `/final`) | транзакції: `acc`, `startDate`, `endDate`, `followId`, `limit` | там само |
| monobank юросіб | `/ext/v1/accounts` | список рахунків | специфікація corp-api v1.0.2 |
| | `/ext/v1/accounts/{iban}/balances` | баланси з `isFinal` | там само |
| | `/ext/v1/statement/{iban}/{from}/{to}` | виписка (`limit`, deprecated `direction`) | там само |
| monobank ФОП | `/personal/client-info` | рахунки; звідси береться ідентифікатор рахунку | персональне API v250818 |
| | `/personal/statement/{id}/{from}/{to}` | виписка | там само |

**Ліміти.** Приват — пауза 1,2 с між запитами (рекомендація банку ≤ 1 запит/с); якщо `/settings` повідомляє, що йде
регламент (`work_balance = Y`), Приват зупиняється. monobank юросіб — 1,5 с між запитами, а коли банк у заголовках
повідомляє про вичерпаний ліміт, рекордер чекає, скільки він просить. monobank ФОП — 61 с між запитами, відрізки
не довші за 31 добу. Ліміти навмисно **не провокуються**; якщо банк усе ж відповів `429`, відповідь записується, рекордер
чекає `retry-after` (або 60 с) і повторює запит **один раз**; другий `429` зупиняє сценарій.
*Єдиний виняток — сценарій `fop_client_info_then_statement_immediately`:* це вимір, який просить архітектурне
рішення D36 п. 9 (чи видає банк виписку одразу після `client-info`). Один запит без паузи на прогін; якщо банк
відповість `429`, це і є результат виміру. Вимкнути можна: `ClientInfoThenStatement = $false`.

**Свідомі помилки** не змінюють нічого в банку: вигаданий недійсний токен (захардкожене очевидно фальшиве значення, не
ваше), початок пізніше за кінець, майбутній період, неіснуючий («чужий») рахунок.

## Сценарії

Скрізь `aN` — номер рахунку з вашого списку.

**ПриватБанк:** `privat_settings`; `privat_aN_balance_period`, `_balance_interim`, `_balance_final`;
`_tx_small_limit` (малий `limit`, кілька сторінок), `_tx_work_limit`, `_tx_default_limit` (без `limit`),
`_tx_no_enddate` (без `endDate`), `_tx_acc_full_iban` (`acc` повним IBAN; основні сценарії йдуть з 14 останніми цифрами,
як у попередника), `_tx_interim`, `_tx_final`, `_tx_charset_cp1251`, `_tx_reversal_period`; помилки `privat_errors_*`.

**monobank юросіб:** `corp_accounts`; `corp_aN_balances`; `_statement_limit500` і `_statement_small_limit` (сторінки
зсувом верхньої межі, як у попередника); `_statement_order_default|UP|DOWN`; `_daily_windows` (запит на кожну добу —
еталон повноти); `_statement_reversal_period`; помилки `corp_errors_*`.

**monobank ФОП:** `fop_client_info_then_statement_immediately`; `fop_statement_segment_NN` (відрізки ≤ 31 доби);
`fop_saturated_segment_NN` (читання, доки сторінка непорожня, — скільки операцій банк віддає за раз);
`fop_reversal_segment_NN`; помилки `fop_errors_*`.

## Другий прогін (потрібен)

Щоб побачити, чи ідентифікатори операцій лишаються тими самими після проміжної виписки (Приват) і після
`hold`/`PENDING` (monobank), потрібен **другий прогін тих самих періодів щонайменше через один робочий день**.
Нічого міняти не треба: той самий скрипт, той самий конфіг, нова мітка прогону.

```powershell
pwsh -NoProfile -File .\Invoke-ApiRecorder.ps1 -RunLabel run2
```

Тека з міткою, яка вже є, не перезаписується (скрипт відмовиться й попросить іншу мітку). Корисно, щоб у перший прогін
потрапили операції «на сьогодні/вчора» (проміжна виписка), інакше їхній перехід у підсумкову не буде видно: тому
`Period` краще закінчувати вчорашнім днем, а перший прогін робити ввечері або вранці після нього.

## Що звірити з кабінетом

Після прогону в консоль і в файл `_owner-only\<банк>__<мітка>__reconcile.txt` виводяться кількості й суми за сценаріями
й валютами (надходження/списання, за станами операцій) і баланси. Порівняйте основні сценарії (`*_tx_work_limit`,
`*_statement_limit500`, `*_daily_windows`, `fop_statement_segment_*`) з випискою в кабінеті банку за той самий період:
кількість операцій і суми мають збігатися. Розбіжність — це і є цінна знахідка, повідомте її планувальнику.

## Самоперевірка: токенів у записах немає

Після кожного прогону рекордер **сам шукає значення кожного токена з вашої конфігурації в кожному записаному файлі**
(включно з розкодованими тілами відповідей) у всіх кодуваннях: UTF-8, UTF-16 (LE/BE), cp1251, cp866, Base64 (будь-яке
вирівнювання), URL-кодування, `\uXXXX`. Якщо знайдено — прогін позначається проваленим (код виходу 3), у консолі
й у файлі `LEAK-DETECTED.txt` названо файл і форму (самого значення не друкується), а теку **не передавайте нікому**;
токен краще перевипустити в банку. Якщо знайдено «ідентифікатор» Привату, це може бути випадковий збіг із числом у
відповіді; повідомте планувальнику, не пишучи значення.

У режимі `-SelfTest` рекордер перевіряє сам пошук без мережі й без ваших токенів: пише файли з вигаданим помітним
значенням у різних кодуваннях і мусить знайти кожне, а на чистих файлах — нуль; ненульовий код виходу означає промах.
Запустіть його перед першим прогоном.

Крім пошуку, токен у запис не може потрапити структурно: заголовків запиту в записі немає, з відповідей беруться лише
дозволені заголовки (`FORMAT.md`).

## Що кому передавати

* **Агенту (через планувальника) — теку запису** `…\api-recordings\<банк>\<мітка>\` разом із `summary-agent.txt`:
  там лише кількості (статуси HTTP, сторінки, операції за станами), без сум, ідентифікаторів, IBAN, імен.
* **Не передавайте** теку `_owner-only` (суми й ідентифікатори), файл `config.psd1` і нічого з консолі з сумами.
* Відповіді банків містять справжніх контрагентів: записи лишаються в `temp/` і в git не потрапляють; у тести вони
  йдуть тільки знеособленими.

## Коди виходу

| Код | Значення |
|---|---|
| 0 | усе гаразд |
