# Інструмент зразків виписок

Відтворюваний ланцюжок «сирий файл виписки → знеособлений зразок + еталон очікуваних операцій». Результат
знеособлення перевіряється автоматично (D22 а/б/в), без перегляду людиною. Інструмент лежить поза
воркспейсом Уніки (автоскан Уніки падає на першому не-UTF-8 файлі, а зразки — у windows-1251); у воркспейс
потрапляють лише готові двійкові макети тестового розширення.

**Сирих даних тут немає й бути не може.** Сирі зразки, їхні робочі копії, мапа «реальне → вигадане» і
знеособлені файли до коміту лежать лише в гітігнорованій `temp/`. У `config.json` — маски шляхів і
службові списки, без жодного реального значення (теку клієнта описано маскою `* - Виписки банка`).

## Запуск

Python 3, **з прапорцем `-P`** (не `-I`: `-I` вимикає користувацький site-packages, де стоїть
`python-stdnum`, потрібний валідаторам). Запускати з теки поза сирими даними.

```
python -P tools/statement-samples/samples.py <команда> ...
```

| Команда | Що робить | Код виходу |
|---|---|---|
| `selfcheck --raw R` | оракул на сирих: кількості, розкладки старих обробок проти розбору «за назвою», звірки ОТП, масштаб `SUMMA`, баланс УкрГазу | 1 при розбіжності з очікуваним |
| `anonymize --raw R --out O` | знеособлює всі зразки з `config.json`, пише `O/<id>.bin` і `O/map.json` (мапа одна на прогін) | 0 |
| `check-a/-b/-c --raw R --out O [--control] [--json F]` | перевірка D22 (а), (б) або (в); для (в) ще й звірка пар форматів | 1 при порушенні |
| `verify --raw R --out O [--json F]` | контроль (а) на сирому + а/б/в на знеособленому + пари | 1 при порушенні |
| `etalons --raw R --out O` | пише `O/<id>.etalon.txt` (формат нижче) зі знеособленого файлу | 0 |
| `epf-list --epf-src epf/src [--exclude Сбербанк] [--out F]` | перелік обробок `epf/src` для матриці формат × зразок (задача 11) | 0 |
| `guard --raw R [--files ...] [--staged]` | сторож перед комітом: лексеми мапи у файлах | 1 при збігах; 2, якщо контроль не падає |

Тести самого інструменту (синтетичні дані): `python -P -m unittest discover -s tests` з цієї теки.

## Оракул: два режими

Оракул — Python-розбір кожного формату двома незалежними лініями:

* **«за розкладкою»** (`sslib/legacy.py`) — емуляція `ЗаполнитьСтроку` нинішніх обробок `epf/src` (колонки за
  номерами, правила напряму, дати, суми). Це не запуск 1С; прийняті припущення про платформу — у
  `PLATFORM_ASSUMPTIONS`;
* **«за назвою»** (`sslib/named.py`) — читачі, що знаходять поле за назвою колонки / поля / атрибута. Збіг двох ліній
  доводить, що розкладка читає саме назване поле.

DBF читається двома моделями, і кожен виклик `util.read_dbf` називає модель (`model=`, значення за
замовчуванням немає): `product` — контейнер `ЗаписиDBF` продукту (NUL → апостроф, справа знімаються лише пробіли,
вилучені пропускаються, номер запису фізичний); `legacy` — XBase старих обробок (значення обрізається на першому
NUL, вилучені пропускаються, номера для людини немає). «За назвою» (`named.py`) представляє продукт, «за
розкладкою» (`legacy.py`) — стару обробку; їх не зіставляти за номером запису.

Режими виходу «за розкладкою»:

* `old` — «стара обробка»: емуляція як є, з усіма особливостями й дефектами;
* `expected` — «очікуване»: стара обробка плюс рівно п'ять відступів плану 03. Кожен відступ — окрема іменована
  функція: `dev1_split_quoted` (лапки в CSV), `dev2_amount` / `dev2_date` / `dev2_currency` /
  `dev2_sens_fop_currency` (нерозібране значення — помилка, не 0; буквений код валюти — числовий; «валюта»
  Сенсу-ФОП — порожня), `dev3_foreign_accounts` (чужі рахунки — у діагностику), `dev4_reader_encoding`
  (кодування заявляє читач), `dev5_oschad_no_temp_file` (DBF читається з пам'яті). Інші відступи, навіть
  очевидні покращення, — питання планувальнику.

Еталон макета рахується в режимі `expected`.

## Знеособлення

Кожне поле кожного формату мусить мати роль (`sslib/schema.py`): `KEEP` (сума, дата, час, валюта, напрям, номер
документа, МФО, коди операцій), `CODE`, `ACC`, `NAME`, `BANKNAME`, `PURPOSE`, `SCRAMBLE`, `DOCTYPE`. Невідома
колонка / поле / атрибут — помилка, а не мовчазне збереження.

* Заміна випадкова (`SystemRandom`); хеші без секрету не використовуються. Мапа одна на прогін і спільна для всіх
  файлів: той самий контрагент чи рахунок отримує ту саму заміну в CSV, DBF і XML, тож звірка форматів
  переживає знеособлення.
* Коди: ЄДРПОУ (8 цифр) і ІПН (10 цифр) — з правильною контрольною сумою; IBAN — mod 97, код банку (МФО)
  зберігається; зв'язок «IBAN ↔ старий номер рахунку» зберігається (одне ядро номера). Довжини збережено.
* Назви: слова замінюються вигаданими тієї ж довжини й регістру; юридичні форми зі списку `allowed_words` лишаються.
* Призначення: фраза зі словника за категорією (комісія, податок, зарплата, відсотки, послуги, товар, інше), яку
  визначає ключове слово сирого тексту. Зберігаються кількість `;`, лапок, керівних символів (NUL, переноси) і
  службових цифр. Шаблонних текстів банку дослівно не лишається (`verbatim_texts` порожній; додавати лише з
  погодженням планувальника).
* Фіксована ширина й DBF: довжина поля — частина структури; вирівнювання (лівосторонє / правостороннє) і байт
  доповнення зберігаються. Байти поза відомими зрізами (проміжки) перемішуються, якщо не порожні й не нулі.
* XLS: підміна на місці в таблиці спільних рядків із тією ж кількістю символів і тим самим кодуванням; числові
  комірки чутливих ролей підміняються як `double`.

## Перевірки D22

* **(а)** жодне чутливе значення сирого файлу не трапляється в знеособленому. Лексикон — усі числа від 5 цифр і
  слова з великої літери (від 3 літер) чутливих полів + повні значення (назви, призначення, коди, рахунки від 6
  символів). Пошук — по всіх байтах знеособленого файлу в трьох поданнях (windows-1251 і UTF-16LE з обома
  вирівнюваннями); для DBF / фіксованої ширини / XLS числа шукаються в межах поля. Із лексикону явно виключаються
  й рахуються: лексеми збережених полів («поля оракула»: сума, дата, номер документа тощо), слова структури
  (заголовки, імена полів / тегів / атрибутів) і `allowed_words`. Залишок поза полями (скелет файлу) мусить
  складатися зі слів структури. **Додатково — шаблонний пошук:** кожен IBAN-подібний рядок і кожне 8/10-цифрове
  число знеособленого мусить бути виданим значенням (є в мапі) або лежати у збереженому полі (дата, сума, номер).
  **Контроль** (`--control`): та сама перевірка на сирому файлі мусить давати збіги.
* **(б)** структура та сама: скелет файлу (усе, крім значень полів) збігається байт у байт; кінці рядків, NUL, BOM,
  кодування; для CSV — кількість рядків і колонок і лапки по кожному полю; для фіксованої ширини й DBF — довжина
  файлу, рядка й поля. У значень: збережені довжини кодів і рахунків, кількість `;` `"` NUL і переносів у назвах
  і призначеннях, контрольні суми (`python-stdnum`: `stdnum.iban`, `stdnum.ua.edrpou`, `stdnum.ua.rntrc`),
  код банку в IBAN.
* **(в)** розбір оракулом (обома лініями) сирого і знеособленого дає однакові значення в усіх полях, крім
  замінених; замінені дорівнюють значенню з мапи. Для пар «та сама виписка у двох форматах» (ОТП `.dat` ↔ `.dbf`,
  `.dbf` ↔ `.xml`) знеособлені версії звіряються між собою так само, як сирі (ті самі кількості збігів по полях).

Скорочені зразки (`take_rows` у конфігурації) порівнюються з сирим файлом, скороченим так само.

## Сторож перед комітом

`guard` бере з усіх сирих зразків числа від 5 цифр і власні назви (поля `NAME` / `BANKNAME`, довжина від 4; слова,
які трапляються також з малої літери, і слова з `allowed_words` / `guard_allowed_words` не беруться) та шукає їх у
файлах (`--files` або `--staged`; імена файлів теж). Нуль збігів — умова точки коміту. Перед роботою сторож
підмішує до нейтрального тексту кілька сирих лексем і вимагає, щоб вони знайшлися (інакше код 2): пошук, який не
вміє падати, нічого не доводить. Сторож призначено для коду, конфігурації, документації й журналу; знеособлені
макети й еталони охороняє перевірка (а) (на випадкових цифрах п'ятицифрові збіги з сирими неминучі).

## Формат еталона `СМП_ТестЭталон<…>` (версія 1)

Текст UTF-8, рядки через LF. Значення екрановані: `\` → `\\`, TAB → `\t`, LF → `\n`, CR → `\r`, тож один
запис — один фізичний рядок; поля запису розділені символом TAB. Рядки, що починаються з `#`, — коментар.

```
# СМП_ТестЭталон
# Версия формата: 1
# Режим: ожидаемое (старая обработка + отступы 1-5)
[Образец]
Идентификатор=<суфікс макета>
Контейнер=csv|lines|dbf|xml|xls
Принимается=Да|Нет
```

Для `Принимается=Нет` (зразок мусить бути відхилений форматом) далі лише `Причина=` (категорія, не значення) і
`ЗаписейИсточника=` (скільки записів розбирає оракул «за назвою»); операцій нема.

Для `Принимается=Да` далі:

```
Схема=<розкладка оракула>
ЗаписейИсточника=<записів у джерелі, без заголовка>
ПропущенныхСтрок=<рядки, які стара обробка пропускає: порожній код у першій колонці>
[Счета]                         власні рахунки у порядку першої появи: НомерСчета TAB кількість операцій
НомерСчетаЧтения=<перший з [Счета]; він же Параметры.НомерСчета у тесті>
[Операции]                      перший рядок — назви колонок:
  ПорядковыйНомер  НомерСчета  Валюта  ДатаОперации  НомерДокумента  Сумма  Направление
  КонтрагентНаименование  КонтрагентНомерСчета  КонтрагентКод  КонтрагентМФО  НазначениеПлатежа
[Диагностика]                   перший рядок — Уровень TAB ПорядковыйНомер TAB Что TAB СырьеЗначение
[ЧужиеСчета]                    перший рядок — НомерСчета TAB НомераСтрок: рядки, чий власний рахунок ≠ НомерСчетаЧтения
```

* `ПорядковыйНомер` — номер у джерелі з одиниці: фізичний рядок файлу (заголовок CSV — рядок 1), запис DBF, елемент
  XML.
* `Валюта` — три цифри або порожньо (= валюта рахунку); `ДатаОперации` — `ГГГГ-ММ-ДДTгг:хх:сс`; `Сумма` — десяткове
  число з крапкою й двома знаками; `Направление` — `Поступило` / `Списано`.
* Колонок `ДатаДокумента` і `ИдентификаторОперации` в еталоні немає: стара обробка їх не читає, тест їх не звіряє.
* `[Диагностика]`: `Что` — `amount` / `date` / `currency` (відступ 2), `СырьеЗначение` — сире значення з файлу.
  На реальних зразках очікувана діагностика порожня.
* `[ЧужиеСчета]` — лише інформація про відступ 3; рівень повідомлення й текст визначає задача 5.

Тест 1С читає макет еталона, розбирає секції й порівнює з тим, що повернув читач на макеті `СМП_ТестВыписка<…>` (або
на тому ж файлі через реєстр). Еталон рахується з **знеособленого** файлу оракулом, а не BSL-кодом, який він
перевіряє.

## Макети тестового розширення

Макети лежать у тестовому розширенні `SMP_BankExchange_SMB_Tests` у власній обробці `DataProcessor.СМП_ТестыМакеты`
(шаблон потребує власника; сама обробка нічого не робить). Тести задач 6–11 дістають макет за ідентифікатором зразка `Ид`
(колонка «Ид» нижче) **лише так**, без власного коду пошуку:

```bsl
Данные = Обработки.СМП_ТестыМакеты.ПолучитьМакет("СМП_ТестВыписка" + Ид);   // ДвоичныеДанные: знеособлений файл
Эталон = Обработки.СМП_ТестыМакеты.ПолучитьМакет("СМП_ТестЭталон" + Ид);    // ТекстовыйДокумент: еталон v1
```

* `СМП_ТестВыписка<Ид>` — макет типу «двоичные данные»: байти файлу без змін (windows-1251 для текстових форматів;
  NUL і кінці рядків збережено). Передавати читачеві як є.
* `СМП_ТестЭталон<Ид>` — текстовий макет (`ТекстовыйДокумент`; у файлі `Template.txt` — UTF-8 з BOM). Читати рядками
  (`Эталон.ПолучитьСтроку(Н)`), розбирати за форматом v1 вище: секції `[Образец]`, `[Счета]`, `[Операции]`, `[Диагностика]`,
  `[ЧужиеСчета]`; поля запису розділені TAB; значення екрановані (`\` → `\\`, TAB → `\t`, LF → `\n`, CR → `\r`). Еталон зразка, який мусить бути
  відхилений, містить лише `[Образец]` з `Принимается=Нет`.
* `СМП_ТестПереченьОбработок` — текстовий макет: імена обробок `epf/src` без Сбербанку, по одному в рядку (для матриці
  «перевірка формату × зразок» задачі 11). Перегенерація: `epf-list --epf-src epf/src --out <файл>`.
  **Перегенеровувати при кожній зміні складу `epf/src`**: тест повноти реєстру не бачить диска й порівнює реєстр лише з
  макетом, тож застарілий макет робить перевірку помилково зеленою.

### Скан зібраних `.epf` на витік

Тестові `.epf`, що збираються з вихідників `tests/epf-src` тестового розширення, — ще одне місце, куди сирі дані
можуть потрапити (контейнер `.epf` стискає вміст, і пошук по сирих байтах файлу стиснутого вмісту не бачить). Тому скан:

* шукає лексеми сторожа не лише в байтах файлу, а й у **розпакованих deflate-потоках** контейнера;
* мусить мати контроль усередині стиснутого потоку: у зібрану для контролю обробку вкладається відома лексема, і скан
  зобов'язаний її знайти (пошук, який не вміє падати, нічого не доводить);
* повторюється після кожної зміни `tests/epf-src`: контейнер недетермінований (повторна збірка дає інші байти), тож
  результат попередньої збірки нічого не каже про нову.

Ідентифікатори (`config.json`, поле `id`; «Прийнятий» — формат читається, «Відхилюваний» — читач мусить відхилити файл):

| `CSVАваль` | прийнятий | iFOBS CSV, Аваль; колонка номера документа зветься «Документ» |
| `CSVВосток` | прийнятий | iFOBS CSV, Восток; кінцевий `;` |
| `CSVУниверсалNUL` | прийнятий | iFOBS CSV, Універсал; NUL у призначенні, кінцевий `;` |
| `CSVПроКредит` | прийнятий | iFOBS CSV, ПроКредит |
| `CSVУкрСиб` | прийнятий | iFOBS CSV, УкрСиб; усі поля в лапках, `;` усередині призначення |

(справжні операції запису з `limit=500`, згруповані моделлю в сторінки на робочому ліміті) має ті самі тіла операцій побайтово й ту
саму множину `id`. Очікуване синтетики D36 п. 11 записане руками в `tests/test_api_d36_p11_by_hand.py` і звіряється з оракулом. Skipped ≠ зелений; контроль моделі вимагає знеособленого run1.

`sets` не кладе в run1 читання, яких конектор не відтворить запит у запит (`readings.replay_exclusion`: параметр `direction`, якого конектор не шле; вікно `balances` з іншого сценарію; запис, що кінчається повною сторінкою без наступного обміну; продовження з `to` = межова секунда, як у рекордера); перелік виключень і причини друкує команда. Розмір сторінки (`limit`) причиною не є: запис із іншим `limit` тест читає зі швом розміру сторінки.

monobank ФОП (задача 5): сторінки й продовження — за тими самими правилами D36 п. 11 всередині кожного відрізка ≤ 31 доби; у запиті виписки
ліміту немає, поріг «повної сторінки» — документальна гіпотеза (500), а синтетика пагінації записана на моделі `FopBank` з меншою сторінкою
(`Params.page_limit`, у еталоні `parameters.РазмерСтраницы` — його задає шов розміру сторінки в тесті). Період ділиться на відрізки в секундах Unix від найновішого, кожен ≤ 31 × 86400 с; запит кожного відрізка бере запас у секунду з обох боків (`from` − 1 с … `to` + 1 с, найновіший — до `Мин(КонецПериода + 1 с, момент читання)`), тож сусідні запити перекриваються на секунду, а повтори відкидаються за `id` (включність `from` / `to` не виміряна).
Момент читання транспорту фіксований записом (`parameters.МоментЧтения`, UTC). Період, що починається пізніше за момент, — запитів немає; перевернутий період (кінець раніший за початок) відхиляє точка читання до конектора. Між запитами виписки пауза 60 с, після
`client-info` паузи немає. Читання run1 ФОП із чужим ідентифікатором рахунку в запиті, з перевернутим або майбутнім періодом конектор не відтворить: `sets` їх виключає.

ПриватБанк (задача 6): запит транзакцій і балансу — цілими днями від дня `НачалоПериода` до дня Мин(`КонецПериода`, момент читання) (`common.privat_days`; обидві дати банк
включає, запасу в день немає), `acc` — 14 останніх цифр рахунку, `limit` 100, `followId` — `next_page_id` попередньої сторінки; кінець — `exist_next_page`. Точний період — фільтр за днем
`DAT_OD` і часом `DATE_TIME_DAT_OD_TIM_P` (секунди завжди 00); розбіжність днів цих полів — `Предупреждение`, `DAT_KL` не використовується. Пауза 1 с між запитами, після 429 — за заголовком
(стеля 120 с). Чужі рахунки конектор не порівнює: операція несе `AUT_MY_ACC` як є, відбирає точка читання. Моделі банку для Привата немає: пагінація курсором, сторінки в синтетиці
записані явно, а запис з малим `limit` — справжній (`ЗапTxSmallLimit`, шов розміру сторінки). Читання run1 Привата, чий запит конектор не відтворить (немає `limit` чи `endDate`, `acc` —
IBAN чи чужий, період навпаки чи в майбутньому), `sets` виключає з причиною (`readings._replay_exclusion_privat`, на правилах `expected.verify_privat_requests`).

Знеособлення й поля KEEP (раунд run3 і фінальне рев'ю): значення ролей ID, ACC, CODE і слова (від 4 літер) ролей NAME / BANKNAME, що стоять підрядком у БУДЬ-ЯКОМУ рядковому полі KEEP (`NUM_DOC`,
`message`, `brnm`, `AUT_*_MFO_CITY` тощо), знеособлювач замінює ТІЄЮ САМОЮ заміною з мапи (`anonymize.Bank.build_sweep`, `clean_text`; цілі значення -- від 6 символів і більш як з 2 різних; слова -- заміна слова з мапи), тож ключ D17
і зв'язок ID <-> REF узгоджені. Перевірка (а) шукає сире значення ролей ID / ACC / NAME в БУДЬ-ЯКОМУ полі, шляху, запиті й тілі як підрядок: від 8 символів -- у байтах у всіх кодуваннях, коротші -- без нижньої межі довжини в розкодованих
значеннях (`step2.scan_short`), слова NAME з великої літери -- за словником. ПОВНИЙ перелік винятків (а), кожен явний: (1) цілі токени з НЕ БІЛЬШЕ ніж двох різних символів (`step2.Sensitive.exempt`: нульові рахунки, круглі суми на кшталт «1» і восьми нулів,
що як фрагмент base64 трапляються в чужих тілах) і цілі фрази, які генератор видає сам (`Sensitive.generic`); (2) обороти/залишки дня Привата, що дорівнюють сумі єдиної операції (роль SCRAMBLE, не ID/ACC/NAME; `step2.PAIRS`, пара Привата); (2б) ПУМБ, `pumb_balance_equals_amount` (A6): значення SCRAMBLE-поля залишку/обороту (`step2.PUMB_PAIR_SOURCES`: `balance`, `rest`, `holds`, `balanceUah`, `restUah`, `holdsUah`, `forecast`, `inWork`, `forecastWithHolds`, `restWithHolds`, `restWithHoldsUah`, `transactionHolds`, `transactionHoldsUah`, `inSaldo`, `outSaldo`, `debitTurn`, `creditTurn`), що стоїть підрядком у `amount` ДОКУМЕНТА searcher чи `amount` ТРАНЗАКЦІЇ period-transactions (KEEP; та сама операція в обох основах; A7), дозволено лише в цих двох полях; будь-де ще (інше поле, зокрема `number`/`documentNumber`, шлях, запит, тіло запиту) -- `pair_leaks`, червоне;
(3) числа від 5 цифр, що збігаються з числом у полі KEEP ЛИШЕ з явного переліку полів (`step2.KEEP_NUM_FIELDS` для банків API: суми, дати й моменти, номери документів; `sens.nums -= keep_nums`): це вже публічні значення, напр. сума в призначенні платежу чи залишок єдиної операції, що дорівнює її сумі (виміряно: ролі PURPOSE і SCRAMBLE;
без винятку 11-14 збігів у Привата й 1 у ФОП саме таких чисел); (4) слова: лише явні словники `allowed_words` / `guard_allowed_words` / `api_guard_allowed_words` з `config.json` (юридичні форми, назви банків, міста) і слова, що їх сам генератор видає у
вигаданих призначеннях (`anonymize.GEN_WORDS`). Неявні винятки `keep_words` («слово є в KEEP того самого запису») і `lower_words` («слово десь трапилось малими літерами») ПРИБРАНО, так само `DLR_in_NUM_DOC`. Той самий `lower_words` прибрано з лексикону
сторожа `sslib/guard.py` (+28 слів, 0 збігів); його виняток для чисел, що збігаються зі збереженим полем зразка, ЛИШЕНО, але звужено до явного переліку ключів (`sslib/guard.KEEP_NUM_KEYS`: суми, дати, номери документів; МФО, коди, ідентифікатори, текст винятку не мають); на наявних даних лексикон не змінився (1997 чисел), макети теж. Поле KEEP поза переліком винятку не має.
Правило для ВСІХ банків (не виняток, A6): роль PURPOSE зберігає клас байтів -- ASCII-оригінал дає ASCII-заміну (`anonymize.Bank.ascii_purpose`: вибір за хешем тексту, окремий детермінований потік, основну послідовність ГПВЧ мапи не зсуває), тож перевірка (б) «кодування тіла» лишається строгою.

виняток `Sensitive.exempt` на них не поширюється, єдине обмеження -- токен з одного символу. Ще один ЯВНИЙ виняток, уже не ролі, а режиму оракула: «стара обробка» для ПУМБ НЕ застосовується (`oracle_old.pumb_not_applicable`, позначка `PUMB-NOT-APPLICABLE`, `Исключение.kind = not-applicable` в `oldProcessing` еталона). Причина -- рішення власника: новий конектор не мусить впізнавати документи, завантажені старою обробкою, сумісність ключа D17 з нею не вимога, завантаження починається з дати; Т1 для ПУМБ цей ключ не звіряє. Таблиця ролей ПУМБ -- гіпотеза за swagger, невідоме поле (зокрема форма помилки) -- зупинка. Оракул і набори ПУМБ -- Step 2-3 задачі 2a.

### Оракул: два режими

**«Стара обробка»** (`oracle_old.py`) — емуляція нинішніх API-модулів (`СМП_РаботаСБанками…APIСервер`) разом з їхніми
фільтрами й виведенням `ДатаДок`. Не запуск 1С: модулі приватні й ходять у мережу без шва (D19). Результат — поля
ключа D17 для кожної операції: `ДатаДокумента`, `НомерДокумента`, `КонтрагентНомерСчета`, `Сумма`. Усі припущення —
в `oracle_old.ASSUMPTIONS` (ідентифікатор -> текст із посиланнями на рядки модулів); еталон перелічує застосовані.

* **ПриватБанк — регламентний шлях** (`ВыполнитьРегламент`, PB:432 -> PB:500, фільтр валюти PB:425-430). Інтерактивний
  шлях валюту рядка не порівнює й тут не відтворюється; якщо еталону знадобляться обидва — СТОП до планувальника.

* Клас відмови (поле конверта `КлассОтказа`; запропоновані значення): порожній рядок; `Повторить`; `ДействиеЧеловека`.
  Принцип — «чи допоможе повтор?». `Повторить`: мережа, таймаут, 408, 429 після дозволеного повтору, 5xx, тіло не JSON,
  `exist_next_page` без `next_page_id`, будь-яка інша нестандартна відповідь. `ДействиеЧеловека`: 401, 403 та інші 4xx,
  рахунку немає в `client-info`. Помилки ПриватБанку, СПОСТЕРЕЖЕНІ в `run1`: HTTP 4xx (401, 400, 403), `status: ERROR`, `code` =
  HTTP-код рядком, `appErrorCode` (SE004, VE017, SE013), без `serviceCode`; клас — за HTTP-кодом. `status: ERROR` при HTTP
  200 не спостерігалося — це документальний варіант (синтетика з позначкою): класифікація за змістом (`code`, `serviceCode` на
  `CLIENT_AUTH*`). `/settings` — обов'язковий перший обмін кожного читання ПриватБанку (R14; без нього «очікуване» не мовчить, а кидає
  `RecordingMismatch`): `work_balance = Y` (іде регламент банку) означає:
  запитів транзакцій немає, `Повторить`, `Предупреждение` (відступ на безпечний бік, `rule_work_balance`); `date_final_statement` у
  межі довіри участі не бере.
* Рівень рядка збою: будь-який збій з непорожнім класом — `Предупреждение` (неповне читання, курсор утримується, втрати
  немає). `Ошибка` — лише операція, яку неможливо подати: невідомий стан, напрям чи валюта, нерозбірні дата чи сума,
  конфліктний дубль, реверс (б).
* `ЧтениеПолное = Ложь` при непорожньому класі та коли сторінковий обхід не довів відрізок до кінця (повна сторінка
  дійшла до початку відрізка юросіб; верхня межа не зменшилась). Прочитане до відмови лишається в `Операции`.
* `ГраницаДоверия` (D36 п. 10) = найраніша з: `КонецПериода`; момент першої неостаточної операції; банківська межа —
  ПОЧАТОК першого дня без ознаки остаточності за подобовими балансами періоду (ПриватБанк — `is_final_bal = true` у `/balance`,
  день рядка — `dpd`, рядки від нових до старих; юросіб — `isFinal = true` у `balances`), а не кінець останнього остаточного
  дня; обмін балансів іде ПІСЛЯ транзакцій; ФОП — лише `hold`. Не раніша за `НачалоПериода`. День без рядка балансу —
  НЕОСТАТОЧНИЙ (`absent_day_is_final`, до виміру False; `dependsOn: ТлумачениеГраницы`). `date_final_statement` у межі
  не бере участі (вимір показав, що поле лежить далеко в минулому); мутація «межа з `date_final_statement`» — червоний тест.
  При непорожньому класі — `НачалоПериода`. Збій обміну балансів — відмова за тим самим принципом (прочитане лишається).
* Кінець читання (D36 п. 11, `rule_end_of_read`): ПриватБанк — за `exist_next_page` (`next_page_id` банк віддає й на ОСТАННІЙ
  сторінці; мутація «йти за наявністю `next_page_id`» червона на записах, де остання сторінка його несе); юросіб — сторінка
  коротша за ЗАПИТАНИЙ ліміт, і робочий ліміт (`CORP_WORKING_LIMIT`) не більший за виміряну нижню межу максимуму сторінки
  (`CORP_MEASURED_MAX_PAGE`, значення й вимір — у журналі плану; мутація «ліміт понад виміряне» червона); продовження за
  часом (юросіб): межа продовження = Мин(E + 1, U) (E -- найраніша `time` повної сторінки, U -- поточна `to`; банк не повертає операцію з `time = to` (журнал 05а, `9e1eb08`),
  журнал `9e1eb08`; межа ніколи не зростає), повтори відкидає дедуплікація за `id`; кількість операцій, кратна ліміту, — остання сторінка лише повторює межову операцію (`СинтКратнаяСтраница`);
  застрягання (межа продовження = U, тобто E >= U - 1) — клас `ДействиеЧеловека`, читання триває з межею Мин(E, U - 1)
  (`cursor-stuck`; діагностика називає секунди U - 1 і U та кількість операцій сторінки); відповідь за межами запиту
  (`time` > `to` або < `from`; `time` = `to` не аномалія) — `Повторить`, ця сторінка в конверт не береться (`out-of-bounds`);
  «є ще» без курсора (в сторінці немає читаного `time`) — `Повторить`. Семантика `to` для дробових секунд не виміряна. ФОП: ліміту в запиті немає, «коротша за 500 — остання» — ДОКУМЕНТАЛЬНА гіпотеза
  (`dependsOn: РазмерСтраницыMono`).
* Порядок операцій усередині однакового моменту: склейка сторінок ПриватБанку й єдиний запит можуть розходитися
  в парах однакового моменту (вимір — у журналі). Еталон ФІКСУЄ порядок записаних сторінок (`ПорядковыйНомер` = позиція у відповідях; відтворення дає конекторові ті самі
  сторінки), а порівняння читань з різним розміром сторінки робить `expected.ops_equal_ignoring_order_within_moment`.
* Дедуплікація за ідентифікатором: фільтр стану СПЕРШУ, як у попередника (неостаточний запис у «баченому» не лишається,
  тож `DONE` з тим самим id на наступній сторінці не губиться); тотожний запис (id і вміст) — один раз; той самий id з
  іншим вмістом, що не реверс, — `Ошибка conflicting-duplicate`. Для ПриватБанку ключ — лише ідентифікатор за D36 п. 6
  (`privat_id`, за замовчуванням `ID`); якщо стабільного немає (`privat_id=None`) — дедуплікації за вмістом нема, дві однакові операції не
  зливаються (D35.4).
* Перелік валют оракула — РІВНО той, що в 1С-функції `ЧисловойКодВалюты` (`СМП_ЧтениеВыписокОбщее`: UAH, USD, EUR, GBP,
  PLN, CHF); `tests/test_api_round1.py` читає BSL-джерело й звіряє (контроль поломкою). Розширювати перелік — лише в BSL.
  Невідомий код -> `Ошибка unknown-currency`.
* Невідомий стан / напрям / валюта, нерозбірні сума й дата — `Ошибка` у діагностику, запис не стає операцією.
* Нульова сума з банку доходить до платформи як є (її відхиляє межа D28 з діагностикою), конектор її не ховає.

### Формат еталона `СМП_ТестЭталон<Банк><Ид>` (версія 1, JSON)

Текст UTF-8, JSON; тест 1С читає його `ЧтениеJSON` (дати — рядки `ГГГГ-ММ-ДДTгг:хх:сс`, суми — рядки з двома знаками).
Повна схема з поясненнями — у шапці `apilib/etalon.py`; коротко:

```
format, formatVersion=1, bank, id, synthetic, title, reviewFocus[]
recording        {макет, обменов}
parameters       {НомерСчета, НачалоПериода, КонецПериода}          // Параметры читання (київський місцевий час)
dependsOn[]      що ще не виміряно й може змінити еталон
expected         ЧтениеПолное, ГраницаДоверия, КлассОтказа,
                 Операции[] (колонки конверта D28 без СырыеДанные), Диагностика[] {Уровень, ПорядковыйНомер, Суть, Отступ, Факты},
                 ЧужиеСчета[], Запросы[] (метод, хост, шлях, пари запиту — у порядку обмінів; обмеження: це КОПІЯ запитів запису, не обчислення
                 з параметрів, тож стверджує те, що зробив рекордер; звірка запитів конектора — транспорт відтворення), Паузы[] {ПослеЗапроса, Секунд, Причина},
                 ОтступыПрименены[]
oldProcessing    Параметры, ПоляКлюча[] (D17), Исключение, Полная,
                 ПропущеноБезСледа[], Допущения[]
```

`Диагностика.Суть` — стабільний код, а не текст (текст ще не визначено): `nonfinal`, `cancelled` (Предупреждение);
`reversal-state-change`, `unknown-state`, `unknown-direction`, `bad-identifier`, `no-iban` (обидва — лише ПУМБ), `bad-amount`, `bad-date`, `unknown-currency`,
`conflicting-duplicate`, `account-not-found`, `read-failed` (Ошибка); `foreign-currency`, `currency-unknown` (Предупреждение, відступ 1 для валюти). `Факты` — банк, статус, опис банку, ідентифікатор;
токена там немає за побудовою. `dependsOn` (мітка того, що не виміряно на справжніх даних; вибір `ID` для ПриватБанку виміряно, але мітка `ИдентификаторПриват` досі виставляється кожному еталону Привата з операціями й тепер означає лише «ключ — наш вибір», а не «вибір не зроблено»; `ФильтрВалютыПриват` — валютні операції Привата стоять на захисті без виміру): `ИдентификаторПриват`, `РеверсСлучай`, `ПаузаПослеClientInfo`,
`РазмерСтраницыMono` (ФОП: гіпотеза документації), `ФильтрВалютыПриват`, `ТлумачениеГраницы`.

### Синтетичні записи

### Самоперевірка оракула

`selfcheck` бере приклади з документації (`doc_examples.py`: ПриватБанк «Приклад відповіді з транзакціями», `example`
полів monobank, обмеження банків на період, сторінку й частоту) і стверджує лише те, що з них випливає: сума в копійках
і знак, `TRANTYPE`, Unix -> київський час із фіксованим зсувом літнього часу (незалежна арифметика, не `kyiv.py`),
склад призначення з полів прикладу, ідентифікатор (`ID`), довжина відрізка ФОП в UTC ≤ 2 682 000 с для кожного дня року.
Контроль: `tests/test_api_selfcheck.py` ламає оракул (правило літнього часу, склад призначення, відступ, вибір
ідентифікатора, напрям, ліміти) і вимагає червоного від відповідних перевірок.

### Step 2: знеособлення справжніх записів і перевірки а / б / в (D22)

Сирі записи (`<корінь>/<банк>/<мітка>/`, формат `FORMAT.md` v1) і мапа «реальне -> вигадане» (`<тека>/<банк>.json`) лежать
ПОЗА робочим деревом і в git не потрапляють; знеособлений вихід — `temp/api-anon/<мітка>/<банк>/` (гітігнорована `temp/`) у
тому самому форматі.

* **Знеособлення** (`anonymize.py`): міняються лише значення полів з роллю не KEEP (`schema.py`: суми, дати, валюта, статуси,
  прапорці, МФО, номер документа лишаються; коди, рахунки, назви, призначення, ідентифікатори, залишки — замінюються).
  Решта тіла лишається **побайтово** (`jsonspan.py`: пробіли, порядок ключів, форма чисел), кодування тіла те саме (cp1251
  лишається cp1251). Невідоме поле — зупинка (`UnknownField`, код 4), у повідомленні лише ім'я поля. Мапа одна на банк: те саме
  значення — та сама заміна в тілах усіх сторінок і в шляхах запитів (IBAN у шляху юросіб, ідентифікатор рахунку ФОП, `acc`
  і `followId` ПриватБанку); `acc` із 14 цифр — хвіст вигаданого IBAN; `ID` = `TECHNICAL_TRANSACTION_ID` і починається з `REF`
  (зв'язок зберігається). IBAN і коди — з правильною контрольною сумою (`sslib.gen`, валідатор незалежний — `python-stdnum`);
  ідентифікатори — вигадані тієї самої форми й довжини (`Fakes.ident`), числа-залишки — те саме за формою (`Fakes.number`).
  Вільний текст KEEP-полів (`message`, `errorDescription`) і текст збою зачищаються від відомих токенів рахунків.
* **(а)** `check-a`: жодне чутливе значення сирого запису не трапляється в знеособленому — по байтах розкодованих тіл і файлів, в усіх
  кодуваннях (UTF-8, UTF-16LE/BE, cp1251, cp866, `\uXXXX` великими й малими, URL-кодування, Base64 зі зсувами 0/1/2), по розкодованих
  рядках JSON, у шляхах і запитах; числа від 5 цифр і власні назви — як у `sslib.guard`. Не вважаються витоком: значення з однієї
  повторюваної цифри (нульовий «неіснуючий» рахунок), частина значення KEEP-поля (політика лишає видимим), загальна фраза словника
  замін. Контроль: та сама перевірка на сирому записі мусить давати збіги (код 2, якщо ні).
* **(б)** `check-b`: скелет тіла (ключі, порядок, типи, довжини масивів, пробіли) побайтово однаковий, KEEP не змінено, заміна має
  ту саму форму (довжина й клас символів), назви й призначення — «порожнє / непорожнє», кодування тіла, заголовки, статуси,
  послідовність обмінів, маніфест.
* **(в)** `check-c`: запис ріжеться на читання (`readings.py`) і доповнюється обмінами `/balance`, `balances`, `client-info`; оракул
  обох режимів на сирому й знеособленому читанні дає ті самі значення в усіх полях, а замінене поле дорівнює значенню з мапи
  (мапа лише читається); запити зіставляються з очікуваними за тією самою мапою.
* `etalons` пише читання (`readings/<банк>/<Ид>/`) і еталони (`etalons/СМП_ТестЭталон….json`) для знеособлених записів;
  читання, яке оракул не може розібрати (запис обірвано рекордером на сторінці з `exist_next_page = true`), пропускається з
  причиною. `verify --report` ганяє а+б+в і пише звіт без значень (команди, кількості, коди виходу).

## Відомі межі

* Емуляція старих обробок — не запуск 1С; припущення про платформу (`legacy.PLATFORM_ASSUMPTIONS`) не перевірені тут.
* Імена в `[Операции]` для ОТП `.dat` беруться за розкладкою старої обробки, яка читає ім'я зі зсувом від межі поля
  (відомий дефект); у перевірці (в) такі імена порівнюються за довжиною.
* Записи API: ПриватБанк, monobank ФОП і юросіб (див. вище); ПУМБ і NovaPay — після специфікацій банків. Файли `settings*` не відкриваються ніколи.
