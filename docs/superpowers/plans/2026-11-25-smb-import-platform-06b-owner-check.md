# Сценарій приймання 6б: читання API з форми завантаження

Для власника. Дев-база, справжні рахунки, один `.cfe` `SMP_BankExchange_SMB` (збірку й дату файлу веде контролер, див. журнал
`2026-11-25-smb-import-platform-06b-api-form-runs.md`, «Вимір контролера»). Токени не показувати на знімках і не вставляти
в чат. Для кожного пункту нижче: що зробити, що мусите побачити.

## Підготовка

- Обробка «Обмін з банком», форма завантаження. Потрібні чотири рахунки з обліковим записом (по одному записові на рахунок):
  Приват, mono ФОП, mono юр, ПУМБ; п'ятий — рахунок без запису або з файловим банком (NovaPay чи «підключаєма обробка»).
- Для пункту 6 — копія облікового запису з навмисно зіпсованим токеном (оригінал не чіпати).

## Кроки

1. **Вибір рахунку (для кожного з чотирьох).** Вибрати рахунок. Видно: поле «Період»; поле облікового запису заповнене й не
   редагується (список вибору немає); поля файлу, формату й текст зовнішньої обробки не видно.
2. **Період «сьогодні».** Залишити період за замовчуванням, натиснути «Прочитати виписку». Видно: текст «Очікування відповіді
   банку…» і кнопку «Скасувати читання»; після читання — план операцій і протокол читання. Документи, що вже є в базі, в плані
   не позначені для завантаження.
3. **Завантаження.** Позначити кілька рядків, завантажити. Протокол і журнал завантаження оновились.
4. **Рахунок без API (п'ятий).** Видно лише файл і формат; періоду немає; читання файлу — як раніше.
5. **Період навпаки.** Початок пізніший за кінець → відмова з текстом, документів не створено.
6. **Недійсний токен.** Вибрати рахунок із зіпсованим записом, прочитати. Видно: блок «Дія людини» з текстом для людини;
   токена, ідентифікатора й пароля в тексті немає.
7. **Скасування.** Запустити читання за довгий період і натиснути «Скасувати читання» під час очікування. Видно: читання зупинилось,
   форма знову доступна, застарілого плану немає.
8. **Облікові дані не видно.** Ні в полях форми, ні в протоколі, ні в діагностиці, ні в журналі реєстрації немає ідентифікатора,
   токена, логіна чи пароля (пошук по журналу за початком токена — порожньо).
9. **«Прочитати решту» (за нагоди).** Стелю на живих рахунках не відтворити (перевірено зондом задачі 3), тож пункт
   необов'язковий. Якщо стеля трапилась: протокол показує прочитане й пропонує решту періоду цілими днями; кнопка
   «Прочитати решту» ставить цей період і читає його; період видно до запуску.

## Що вважати провалом

- Потрібне поле є, а обліковий запис можна змінити, або поле порожнє при наявному записі.
- Для рахунку з API видно файл чи формат (або навпаки для файлового).
- У будь-якому тексті або журналі — токен, ідентифікатор клієнта, логін чи пароль, чи текст винятку замість нейтрального
  рядка «помилка в коді конектора банку …».
- Читання без тексту очікування й без кнопки «Скасувати читання»; скасування не зупиняє читання.
- Період навпаки не дає відмови з текстом або створює документи.
- Документ, що вже є в базі, позначений до завантаження.
- Після завантаження протокол чи журнал завантаження не оновились.
