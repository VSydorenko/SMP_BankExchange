## Зонд задачі 0: відмова вендора в проведенні всередині транзакції тесту (крок 3)

**Умова виміру.** 2026-10-14, платформа 8.3.27, YaXUnit 25.12, спільна серверна база SMB; документи
`ПоступлениеНаСчет` / `РасходСоСчета` будує `СМП_ТестыДанныеУНФ.НовыйБанковскийДокумент`; усі тести `.ВТранзакции()`,
один `Записать` у зовнішній транзакції; `КонтролироватьОстаткиПриПроведении = Нет` у базі (константа лише читалась).
Спершу зонд-спостерігач (червоні тести, що виводили протокол), потім — зелені тести-фіксації в модулі
`СМП_ТестыВендораЗаполнениеДокумента`.

| Що міряли | Виміряно |
|---|---|
| (а) Чи живе транзакція після винятку проведення | Ні. `ТранзакцияАктивна()` лишається `Истина`, але будь-який запит (навіть `ВЫБРАТЬ ПЕРВЫЕ 1 … ИЗ Справочник.Валюты`) падає: «В данной транзакции уже происходили ошибки!». Однаково для `Записать(Проведение)` у `Попытка` і для `Записать()` + `Записать(Проведение)` (проба на документі `ПоступлениеНаСчет` без контрагента і на `РасходСоСчета` за новим банківським рахунком) |
| Відновлення | Єдиний знайдений спосіб — `ОтменитьТранзакцию()` + `НачатьТранзакцию()` (перевірено також: окремий `Записать()` перед проведенням транзакцію не рятує; вкладена `НачатьТранзакцию` без відкату і `ЗафиксироватьТранзакцию` не пробувались): `ТранзакцияАктивна` стає `Нет`, потім `Да`, запити працюють. Ціна — відкат усього, що тест створив у транзакції: документ, якому відмовили, і раніше проведений контрольний документ після цього відсутні |
| (б) Причина відмови | Лише текст винятку: `КраткоеПредставлениеОшибки` = «Запись не верна! Не заполнен счет кредита (Регистр бухгалтерии: Журнал проводок; Номер строки: 1)» (виняток із `ОбработкаПроведения`, запис регістра бухгалтерії). `ПолучитьСообщенияПользователю(Истина)` після винятку порожній |
| (в) `ПроверитьЗаполнение()` і проведення | `ПроверитьЗаполнение()` не кидає виняток, транзакція жива, повідомлення («Поле "Контрагент" не заполнено», «Поле "Статья" не заполнено») — у `ПолучитьСообщенияПользователю(Истина)`. `Записать(Проведение)` з коду проверку заполнения НЕ виконує: документ з порожньою статтею (`ПроверитьЗаполнение` = `Ложь`) проводиться (`Проведен = Да`). `ПроверитьЗаполнение` не передбачає і відмову проведення: на другій пробі (`РасходСоСчета`, новий банківський рахунок) воно `Да`, а проведення відмовляє |
| Контроль | Неспотворений документ тим самим будівником проводиться (`Проведен = Да`) — відмова не властивість фікстури |

Тести-фіксації (`СМП_ТестыВендораЗаполнениеДокумента`): `Отказ_ИсключениеПроведения_ТранзакцияМертваВосстановлениеОтменойИНачалом`

Прогін: модуль `СМП_ТестыВендораЗаполнениеДокумента` на дереві `HEAD` = `51d563a` + незакомічені зміни тестів
(`tests/src`: модуль, його `.xml`, `Configuration.xml`; продукт `cfe/src` не змінено), `SMP_BankExchange_SMB_Tests`
перезібрано `fullRebuild` о 16:57: `total=4, passed=4, failed=0, skipped=0, errors=0`. Потім `СМП_ТестыФикстур`
(сторож останнім): 216 / 216. Колір належить коміту A (зелений на його дереві, продукт — `96130b6`).
Раунд правок 1 (рецензія задачі 0): тест (в) доповнено перечитуванням документа з бази, тест (а) — умовою `КонтролироватьОстаткиПриПроведении = Ложь`. Прогін 17:09 (`SMP_BankExchange_SMB_Tests` `fullRebuild` 17:08, HEAD `1a06a38` + правка тестів, продукт `96130b6`): `СМП_ТестыВендораЗаполнениеДокумента` `total=4, passed=4, failed=0`; потім `СМП_ТестыФикстур` 216 / 216.

**Що НЕ виміряно.**
- Відмова проведення через `Отказ = Истина` без винятку: обидві проби відмовили винятком із запису регістра бухгалтерії.
- Контроль залишків (`ВыполнитьКонтроль`): у базі вимкнений (`КонтролироватьОстаткиПриПроведении = Нет`), константа не
  змінювалась; режим, якого в базі немає, не вмикався.
- Поведінка поза зовнішньою транзакцією (прод, регламент, форма).
- Причина відмови на другій пробі (новий банківський рахунок без бухгалтерських налаштувань) — припущення, не досліджувалось.
- Друга проба зонду (`РасходСоСчета` за новим банківським рахунком: `ПроверитьЗаполнение` = `Да`, а проведення відмовило) НЕ зафіксована жодним зеленим тестом: вона виміряна лише зондом-спостерігачем; причина відмови не з'ясована (гіпотеза — новий банківський рахунок без бухгалтерських налаштувань), тож тест на ній був би прив'язаний до невстановленої причини. Її висновок («`ПроверитьЗаполнение` не передбачає відмову проведення») тримається на ній одній і лишається вимірюванням зонду.
