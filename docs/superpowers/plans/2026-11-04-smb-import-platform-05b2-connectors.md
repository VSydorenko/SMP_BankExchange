## Що відомо про попередників (читання коду, 2026-11-04)

Прочитано планувальником, запуском не перевірялось; задача 0 і записи міряють те, на чому стоять
рішення. Модулі — `SMP_BankExchange_SMB/cfe/src/CommonModules/`.

**ПУМБ** (`СМП_РаботаСБанкамиПУМБAPIСервер`, ~750 рядків):
- Пароль-грант на хост автентифікації (`client_id`, `client_secret`, логін, пароль, форма
  `x-www-form-urlencoded`), токен при кожному читанні. Виписка — хост `service`, **порт 4103**;
  `Authorization: Bearer`, `X-App-Channel: pure-api`, `X-Flow-ID` (у попередника константа; інструкція
  банку: обов'язковий, `<GUID запиту>:<GUID сесії>:<відбиток джерела>`).
- Рахунок: `GET /account` → `accountId` за IBAN (попередник ще й за назвою валюти). Виписка:
  `POST /document/searcher`, JSON: `fromDate`/`toDate` `dd.MM.yyyy HH:mm:ss`, `documentState=["PROCESSED"]`,
  `documentType=["UAH"]`, `documentAccounts=[accountId]`. **Пагінації попередник не використовує**,
  хоча схема має `pagingRequest`: **можлива мовчазна втрата в попереднику** (вимір задачі 1).
- Поля: номер і ключ — `id`, інакше `docId`; `ДокументИД` — `docId`; сума — `amount`; сторони —
  `correspondent*`/`sender*`; призначення — `description`; дата — `operationDate`; напрям — `senderIBAN` =
  рахунок → вихідний; код валюти 980 лише для `type=UAH`; `ДатаДок` модуль не ставить — виводить
  `Обработки.СМП_КлиентБанк.РаспознатьДанныеВСтрокеДокумента`. Валютних рахунків не читає. Регламент
  читає вчорашню добу.
- Документація: swagger і `Инструкция.docx` у власника (`swagger.json` sha256 `b6e0965c…`,
  `Инструкция.docx` `08ff0f0b…`); `settings.txt*` не відкриваються ніколи. У swagger: `/account`,
  `/document/searcher` (`DocumentFilter`, `VeganetDocumentItem`: `id`, `hostId`, `docId`, `state`, `type`,
  `direction`, `operationDate`, `createdOn`, `accountId`, `userIdentity`, `responsible`, підписи…),
  `/document/period-transactions` (`inSaldo`/`outSaldo`, `transactionId`), `PagingRequest` (`pageSize`,
  `pagingSessionId`, `orderedLastValue`, `orderedLastId`, `direction`, `sortField`). Ознак остаточності,
  лімітів, `429` у специфікації немає.

**NovaPay** — відкладено разом із NovaPay (нове API банку); читання його попередника в цьому плані не
ведеться.

**Платформа** (5а): реєстр і точка читання `СМП_ЧитателиВыписок` (рядки `ПриватБанк_API`,
`Монобанк_API`, `МонобанкЮр_API`; склад облікових даних — масив імен), `СМП_КоннекторыБанковОбщее`,
транспорт `СМП_ТранспортHTTP` (метод довільний, тіло `Строка` UTF-8 без BOM або `ДвоичныеДанные`,
заголовки довільні, порт є), відтворення `СМП_ТестТранспортВоспроизведение` (звіряє метод, хост **без
порту**, шлях, запит; **тіла не звіряє**), `СМП_ТестЗаписиAPI`.

Діють без змін Global Constraints плану 05а (файлова база, тести без мережі, секрети, записи як зразки
виписок, рекордер лише читає, переносимість воріт `СМП_КоннекторБанка*`, нічого не видаляти D7, старі модулі
лише читаються D19, префікс `СМП_`, дані в транзакції `СМП_ТЕСТ_`, ліцензія — СТОП, точкові коміти, колір
тесту належить коміту). Журнал — `…-05b2-connectors-runs.md`. Додатково:

- **Облікові дані — склад як властивість рядка реєстру; значення ніде** (діагностика, виняток,
  `СырыеДанные`, журнал реєстрації, запис відповіді). ПУМБ: `ИдентификаторКлиента`, `СекретКлиента`,
  `Логин`, `Пароль`. NovaPay (склад, необов'язкові поля, Р1) — відкладено разом із NovaPay. **Імена
  полів складу фіксуються до першого макета** (журнал, задача 2a крок 1); зміна після — перегенерація макетів.
- **Значення, видані банком у ході читання** (ПУМБ `access_token`) платформа не знає; конектор не кладе
  їх у тексти. **Заголовки відповіді автентифікації** (`Set-Cookie` тощо) у діагностику й `СырыеДанные`
  не йдуть. Т2 конектора покриває це значення, ці заголовки й ідентифікатори рахунків (`accountId`)
  маркерами.
- **`X-Flow-ID` ПУМБ:** GUID запиту й сесії — випадкові з транспорту/конектора; відбиток джерела —
  константа без облікових даних і персональних даних; у діагностику не потрапляє.
- **Межі запиту.** ПУМБ — дати з часом (секунди, київський час); якщо вимір покаже, що `operationDate` без
  часу, ПУМБ працює як Приват (цілі дні + фільтр, запасу в секунду немає; урок `d392bc4`). Включність
  меж, не виміряна, — запас (секунда).
- **Майбутній, перевернутий, після моменту.** Верхня межа запиту ≤ момент транспорту; період, що
  починається після моменту, — без запитів, порожній конверт, `ЧтениеПолное = Истина`,
  `ГраницаДоверия = НачалоПериода`; перевернутий період відхиляє точка читання **до** конектора; порядок —
  навпаки, потім майбутнє, потім звичайне читання.
- **Відмова й межа довіри.** Непорожній клас → `ГраницаДоверия = НачалоПериода`, `ЧтениеПолное = Ложь`;
  межа, раніша за початок, затискається до `НачалоПериода`; межа ≤ момент читання; рядок відмови —
  `Предупреждение`, текст називає банк, статус, опис банку, облікових даних не містить;
  відмова автентифікації ПУМБ — `ДействиеЧеловека`.
- **Стеля сторінок і стеля паузи** — константи з обґрунтуванням і позначкою **«гіпотеза»**, доки немає
  виміру. Стеля сторінок більша за кількість сторінок, яку дає обсяг, названий в обґрунтуванні; понад
  стелю — `ДействиеЧеловека`, діагностика називає **сторінки, операції, межу зупинки й пропонує звузити
  період**; стеля паузи не менша за виміряний інтервал банку; нерозібраний заголовок — пауза за
  замовчуванням; понад стелю — `Повторить` без сну й з названою запитаною паузою (заголовка може не
  бути — тоді гілка синтетична й так названа).
- **Аномалія меж, застрягання, курсор, що не просувається** → як у 5а (`Повторить` для аномалії, `ДействиеЧеловека`
  для застрягання й курсора).
- **Кінець читання — за явною ознакою банку** (D36 п. 11). ПУМБ (Р4, редакція 5): явної ознаки кінця
  `searcher` не дає, розмір сторінки не дотримується (`pageSize` 5 → 6 елементів), курсор не виміряно → **API
  без пагінації** (D36 п. 11, абзац «API, що віддає період однією відповіддю», `e937fbd`): запит без
  `pagingRequest` за весь період; відповідь розміром ≥ порога → період ділиться навпіл аж до доби; доба на
  порозі → `ДействиеЧеловека` (неповне, діагностика називає добу й кількість). Поріг — константа з позначкою
  **«гіпотеза»** до виміру максимуму (`run2`). Курсор і `pagingRequest` конектор не використовує.
- **Похідні записи й модель — лише з виміряного** (модель спершу відтворює справжній запис поле за полем).
- **Ручне очікуване** для правил D36 п. 8, 10, 11 записує виконавець руками зі
  спеки й звіряє з оракулом (`tests/test_api_d36_p11_by_hand.py` — зразок).
- **Виключення записів з набору — лише з причиною**; без причини — дефект набору.
- **Маска на вході** для скриптів по сирих записах; **помилка розбору не друкує фрагмент вхідного
  тексту, лише позицію й код**.
- **Знеособлення — без прихованих винятків:** жодного явного пропуску за парою полів чи словом (уроки
  5а: `DLR_in_NUM_DOC`, `keep_words`, `lower_words`); значення ролей ID/ACC/NAME/CODE — підрядком у всіх
  полях, включно з KEEP, у шляху, запиті, **тілі запиту**, тілі відповіді; усі кодування, розкодовані
  рядки; явні словники й `KEEP_NUM_FIELDS` — перелік у журналі з причиною кожного. **Одна мапа
  знеособлення на всі прогони банку** (інакше вимір стабільності ідентифікаторів хибний).
- **Дефект попередника — іменований відступ** (функція оракула, рядок звіту власнику).

**Відступи від попередника — лише ці** (кожен — іменована функція режиму «очікуване»; інший — питання
планувальнику):

8. пагінація й паузи — невидимо в даних; якщо попередник без пагінації втрачав операції — окремий пункт
