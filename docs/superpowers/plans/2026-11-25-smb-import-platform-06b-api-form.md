# Платформа завантаження виписок SMB — план 6б: читання API у формі

## Шапка

- **Статус:** чернетка автора, аудит — розділ «Підсумок аудиту». Приймає архітектор `smp-bankexchange-60`.
- **Гілка:** `feature/smb-import-platform`, від `359540c` (блок «Спрощення» прийнято 2026-11-25). Незлитих якорів
  немає.
- **Режим робочої копії:** `shared` — основне дерево `R:\github\SMP_BankExchange`, без worktree, без
  паралельних виконавців.
- **Спільний рантайм:** серверна база агента SMB (`docs/known-state.md`, «База агента SMB»). Тримає один
  виконавець за раз: `push` source-set `SMP_BankExchange_SMB`, потім `SMP_BankExchange_SMB_Tests`, лише з
  `sourceSet`; збірка без `sourceSet` і `kit provision` заборонені. Тимчасовий зонд вантажиться разом із
  тестовим розширенням і **не комітиться**; перед комітом задачі зонд прибрано, `push` повторено.
- **Заборони:** курсор, стан обміну, глибина регламенту — не з форми (D18 п. 7, ADR-0014); перемикання кнопки
  журналу «Банк і каса» — етап 8 (ADR-0020); NovaPay — поза обсягом; `ConfigurationRepository*` — ні.
- **Рішення архітектора за розвилками** (повідомлення 2026-11-25, від `359540c`): Р-А варіант 1, Р-Б варіант 1,
  «кілька облікових записів — відмова». Поправки спеки — блоком «Правка спеки», спеку править архітектор
  при прийманні.

## Мета / Архітектура / Спека

**Мета.** Концепція старої обробки (рішення власника 2026-11-25): людина вибирає **банківський рахунок**,
програма сама знаходить обліковий запис і джерело. Рахунок з API — на формі лише період; рахунок з файлом —
лише файл і формат, без періоду. Один рахунок за раз. Після читання API — той самий план, запис і протокол,
що для файлу.

**Архітектура.** Один новий серверний вузол — «джерело читання облікового запису» в модулі менеджера
`СМП_ОбменСБанком`: рахунок → обліковий запис → вид джерела (файл / конектор) і рядок `РеестрКоннекторов`.
Облікові дані читає з облікового запису лише серверна гілка читання всередині фонового завдання — за
посиланням на обліковий запис, не з `Вход`. Читання API йде тією самою тривалою операцією
`ПрочитатьИРаспознатьВыписку`, що й файл: розгалуження лише на кроці «прочитати», далі розпізнавання,
адреса плану, протокол — спільні. Конверт отримує додаткове поле прочитаного відрізка (ставить ядро
конекторів при стелі); форма за ним пропонує решту періоду.

**Спека** `docs/superpowers/specs/2026-10-12-smb-import-platform-design.md`: D5 (знайдені не позначаються й
для API), D10 (форма подібна до старої), D18 п. 7 (інтерактив без курсора), D36 п. 3 (облікові дані — нижче
поправка), п. 8 (клас відмови, очікування — питання форми), п. 11 (стеля сторінок, звуження періоду;
межі — київський час). `docs/architecture/connectors.md` §2–§6. ADR-0014, 0017, 0018, 0020.

## Глобальні обмеження

- Keep-набір тестів (блок «Спрощення», журнал `docs/superpowers/plans/2026-11-24-smb-import-platform-simplify-runs.md`) лишається зеленим; змінюється лише там,
  де задача це називає.
- Форма: у макеті все видиме, ховає код; `<Visible>false</Visible>` у формах обробки — 0.
- Тексти для людини — `НСтр(ru; uk)`; внутрішні літерали класів відмов людині не показуються.
- Конектори й ядро не змінюють поведінки читання; єдина зміна ядра — заповнення нового поля при стелі.
- Нових метаданих довідника `СМП_УчетныеЗаписиБанков` немає (реквізит джерела й сховище облікових даних —
  етап 5б).
- Код 1С шукається й читається Унікою (`unica.search`, `unica.view`), правиться — Унікою чи Edit з
  перевіркою `git diff` (пам'ять: Уніка переписує XML).

## Рішення

| # | Рішення | Вплив на спеку |
|---|---|---|
| 1 | **Джерело читання облікового запису (Р-А.1).** Одна серверна функція модуля менеджера: `Банк` облікового запису → рядок `РеестрКоннекторов` (`ПриватБанк`→`ПриватБанк_API`, `МОНОБанк`→`Монобанк_API`, `МОНОБанкЮр`→`МонобанкЮр_API`, `ПУМБ`→`ПУМБ_API`); `NovaPay`, `ПодключаемаяОбработка`, порожньо → файл. Етап 5б замінює лише тіло функції | D36 п. 3 — поправка П1 |
| 2 | **Облікові дані не покидають серверну гілку читання.** Функція з рішення 1 повертає формі лише вид джерела й ідентифікатор рядка реєстру; облікові дані — окрема серверна функція без `Экспорт` у модулі менеджера, яку кличе лише `ПрочитатьИРаспознатьВыписку` у фоновому завданні за `Вход.УчетнаяЗапись` | немає (D36 п. 3 вимога) |
| 3 | **Людина не вибирає обліковий запис.** Поле `УчетнаяЗапись` лишається в макеті, лише для перегляду; список вибору прибирається. Записів рахунку 0 → форма працює як зараз для рахунку без запису (файл, формат за МФО); 1 → він; >1 → відмова читання з текстом «кілька облікових записів для рахунку» і їхніми назвами (крайній випадок: довідник контролює унікальність рахунку) | немає |
| 4 | **Видимість за джерелом.** Конектор → видно період; не видно `ИмяФайла`, `ИдентификаторФормата`, `ТекстВнешнейОбработки`, попередження формату. Файл → навпаки, періоду не видно. Ховає `ОбновитьДанныеСчетаНаСервере` | немає (D10) |
| 5 | **Період людини.** Реквізит форми `Период` (`СтандартныйПериод`), за замовчуванням — сьогодні. У точку читання — `НачалоДня(Начало)` і `КонецДня(Конец)`, включні; дати — київський місцевий час, як дає людина (D36 п. 7, 11). Кінець у майбутньому дозволено: межу довіри обмежує конектор. Початок пізніше кінця — відмова точки читання з текстом (уже є в `ЧитатьКоннектор`), форма запитів не робить. Період у формі не зберігається між відкриттями | немає |
| 6 | **Транспорт.** Серверна гілка створює справжній транспорт `Обработки.СМП_ТранспортHTTP`. Точка входу для зонда — серверна функція модуля менеджера, що приймає транспорт параметром (експортна, без «тестового режиму»); `ПрочитатьИРаспознатьВыписку` кличе її зі справжнім. Це не прапорець, а явний параметр, як у `ЧВ.ПрочитатьКоннектором` (D36 п. 1) | немає |
| 7 | **Очікування.** Форма під час читання API показує текст «Очікування відповіді банку…» і кнопку «Скасувати» (як для файлу, `ДлительныеОперации`, `ОтменятьПриЗакрытииФормыВладельца`). Прогресу немає: конектор його не звітує. Запитані банком паузи — лише в діагностиці підсумку | немає (D36 п. 8 «питання форми») |
| 8 | **Неповне читання — за класом відмови й `ЧтениеПолное`, не за рівнем рядка.** Результат читання для форми несе клас відмови (а не лише булеве `ЧтениеНеполное`). Протокол читання показує окремий блок: «Повторити» — «банк тимчасово не відповів, прочитане завантажується, повторіть пізніше»; «Дія людини» — текст діагностики конектора; повне читання — блоку немає. Автоматичного повтору немає | немає |
| 9 | **Прочитаний відрізок (Р-Б.1).** Конверт `СМП_ВыпискаБанка.НоваяВыписка` отримує поле `ПрочитанныйОтрезок` — `Структура(Начало, Конец)` або `Неопределено`. Ставить лише ядро `СМП_КоннекторыБанковОбщее.ДостигнутПотолок`: межі охопленого читанням до зупинки, київський час. Інші відмови й файлові читачі поле не заповнюють; старі споживачі його не читають. Ядро знає межу зупинки (`Момент`) і межі періоду; напрям (від початку чи від кінця) ядру передає конектор у виклику `ДостигнутПотолок` — форма напряму не знає | D36 п. 11 і `docs/architecture/connectors.md` §6 — поправка П2 |
| 10 | **«Дочитати решту».** Є `ПрочитанныйОтрезок` → протокол пропонує період «решта поза відрізком» (одна суцільна частина, бо відрізок прилягає до однієї межі періоду) і дію «Прочитати решту»; натиск ставить період форми й запускає читання, людина бачить період до запуску. Прочитане до стелі вже в плані — його завантажує людина звичайним шляхом; дублі повторного читання ловить крок 0 (вже завантажено, D5). Без відрізка дії немає | немає (П-М плану 06 замінено рішенням Р-Б) |
| 11 | **Валюта рахунку.** Серверна гілка дає `ВалютаСчета` — числовий код валюти банківського рахунку рядком з 3 цифр (D36 п. 2), з `БанковскийСчет.ВалютаДенежныхСредств` | немає |

## Інтерфейси

- **Дає:** поле конверта `ПрочитанныйОтрезок` (рішення 9) — і для регламенту 5б, щоб просувати курсор після
  стелі (причина вибору архітектора); функція «джерело читання облікового запису» — тіло міняє 5б.
- **Бере:** `СМП_ЧитателиВыписок.ПрочитатьКоннектором`, `РеестрКоннекторов`; `СМП_ЗаписьДокументовБанка.КонтекстыИзУчетнойЗаписи`;
  `СМП_РаспознаваниеОпераций.Распознать`; транспорт `СМП_ТранспортHTTP`; запис і протокол 6а без змін.
- **Форма ↔ сервер:** `НовыйВходЧтения()` отримує `НачалоПериода`, `КонецПериода` (порожні для файлу); вид
  джерела сервер визначає сам за обліковим записом, `Вход` його не несе. Облікових даних у `Вход` немає.

### Задача 1 — джерело читання облікового запису й шапка форми

- **Що:** функція рішення 1 і 3 у модулі менеджера (замість вибору в `ДанныеФормы`); облікові дані —
  окрема функція без `Экспорт` (рішення 2, лише мапа; кличе її задача 2); форма: `УчетнаяЗапись` лише для
  перегляду, реквізит і поле `Период`, видимість за джерелом (рішення 4, 5) в `ОбновитьДанныеСчетаНаСервере`.
  Параметр `БанковскийСчетОрганизации` і команда обробки — як є (відкриття без рахунку: людина вибирає рахунок).
- **Done-when:** рахунок з `Банк` конектора показує лише період; рахунок без запису чи з файловим `Банк` — лише
  файл і формат; >1 запис — текст відмови; `<Visible>false</Visible>` у формах обробки — 0 (пошук по
  `Form.xml` обробки, вивід у журнал).
- **Після:** 0. **Сходинка:** `syntax`; поведінку видимості — тимчасовий зонд функції джерела на трьох
  облікових записах бази агента (створює й видаляє зонд у транзакції). **Оцінка:** ~90 рядків.

### Задача 2 — читання API тривалою операцією

- **Що:** `НовыйВходЧтения` + період; у `ПрочитатьИРаспознатьВыписку` гілка «конектор»: облікові дані за
  `Вход.УчетнаяЗапись` (функція задачі 1), `ВалютаСчета`, `НомераСчетаДляЧтения`, межі дня (рішення 5),
  справжній транспорт через точку входу з параметром транспорту (рішення 6) → `ЧВ.ПрочитатьКоннектором` →
  далі спільний шлях. Результат для форми несе клас відмови (рішення 8) і `ПрочитанныйОтрезок`. Форма:
  текст очікування й «Скасувати» (рішення 7). `КонтекстыИзУчетнойЗаписи` — до читання, як для файлу.
- **Done-when:** тимчасовий зонд точки входу з транспортом, що відтворює записані відповіді 5а (так, як їх
  відтворюють `СМП_ТестыКоннектора*`), без мережі, у транзакції: (1) повне читання Привата → план не
  порожній, класу немає; (2) відповідь «повторити» → клас «Повторить», прочитане в плані; (3) період навпаки →
  текст відмови точки читання, транспорт не викликався жодного разу; (4) знайдені документи в плані
  `Загружать = Ложь` (D5). Висновок — у журнал; зонд не комітиться. Перевірки Б2, Б4 — у журнал.
- **Після:** 1. **Сходинка:** `syntax` + зонд. **Оцінка:** ~110 рядків.

### Задача 3 — прочитаний відрізок і «дочитати решту»

- **Що:** поле `ПрочитанныйОтрезок` у `НоваяВыписка` (рішення 9); `ДостигнутПотолок` отримує напрям від
  конектора й заповнює поле; три конектори зі стелею передають напрям; у ПУМБ стелі немає — без змін.
  Форма: блок протоколу неповного читання (рішення 8) і дія «Прочитати решту» (рішення 10). Якщо задача 0 (а)
  показала перевірку точного складу конверта — розширити її полем.
- **Тест:** keep-тест стелі в одному з `СМП_ТестыКоннектора*` (того, де вже є шов `ПотолокСтраниц`, —
  виконавець називає модуль у журналі) отримує одне твердження: при стелі `ПрочитанныйОтрезок` заповнено й
  межа зупинки — його внутрішня межа. Це контракт ядро ↔ форма/регламент. Мутація: ядро не заповнює поле →
  червоний.
- **Done-when:** keep-модуль конекторів зелений із новим твердженням (мутація — у журнал); зонд форми на
  записах monobank (від кінця) і Привата (від початку) з малою стелею → запропонована решта — інша частина
  періоду в кожному напрямку.
- **Після:** 2. **Сходинка:** `yaxunit` (модуль тесту стелі). **Оцінка:** ~70 рядків продукту, ~10 тесту.

### Задача 4 — інваріант Б1 тестом

- **Що:** один keep-тест у `СМП_ТестыКоннекторовОбщее` (зона маскування; новий модуль не заводиться): точка
  входу рішення 6 на записаних відповідях ПУМБ і Привата з синтетичними секретами, включно з відповіддю,
  де банк повертає тіло запиту в тексті помилки; перевірка всієї структури результату для форми й плану з
  тимчасового сховища на всі форми секрету. Точка входу бере облікові дані лише з облікового запису (шва
  для облікових даних немає): тест створює обліковий запис у транзакції із синтетичними значеннями й
  відкочує. Виклик продукту — через `СМП_ТестыВызовПродукта`, як інші тести модуля менеджера.
- **Done-when:** тест зелений; мутація Б1 (маскування вимкнено в одному місці ядра) → червоний → повернення
  → зелений; вивід — у журнал.
- **Після:** 2. **Сходинка:** `yaxunit`. **Оцінка:** ~60 рядків тесту.

### Задача 5 — документація, наскрізна перевірка, `.cfe`

- **Що:** `docs/architecture/connectors.md` §3 і §6 — прочитаний відрізок і джерело облікових даних до 5б (без чисел і рядків
  коду); `docs/architecture/testing.md` — нові твердження в зоні, якщо таблиця зон їх перелічує; рядок 6б у
  дорожній карті `docs/superpowers/plans/2026-10-12-smb-import-platform-roadmap.md`; сценарій живої
  перевірки для власника — у журналі, на одну сторінку (нижче).
- **Done-when:** весь keep-набір зелений на серверній базі агента (`total` кожного модуля — як у журналі
  «Спрощення» плюс твердження задач 3–4); `make` `.cfe` `SMP_BankExchange_SMB` — дата файлу пізніша за
  старт задачі; `<Visible>false</Visible>` у формах обробки — 0; `doc anchors` плану й змінених документів
  без зламаних; рядок дорожньої карти є.
- **Після:** 1–4. **Сходинка:** `acceptance` (власник). **Оцінка:** документи.

**Сценарій власника (дев-база, справжні рахунки, один `.cfe`):** для кожного з Приват, mono ФОП, mono юр,
ПУМБ — відкрити обробку, вибрати рахунок → видно лише період, поле облікового запису заповнене й не
редагується; період «сьогодні» → очікування, план; знайдені документи не позначені; завантажити → протокол
і журнал оновились. Рахунок з файлом → лише файл і формат. Період навпаки → текст без запиту. Недійсний
токен (тимчасово зіпсований в обліковому записі копії) → блок «дія людини» без токена в тексті. «Скасувати»
під час читання. Стелю на живих рахунках не відтворити — перевірено зондом задачі 3.

## Правка спеки (текст для архітектора; спеку править архітектор при прийманні)

**П1 — D36 п. 3, після «Звідки платформа їх бере — етап 5б (D23, D26).»** Додати: «До етапу 5б інтерактив
бере облікові дані з наявних реквізитів облікового запису (`ИД`, `Токен`, `Логин`, `Пароль`) за мапою
попередника, а рядок реєстру конекторів — за реквізитом `Банк`. Мапа живе в одній серверній функції
обробки форм; етап 5б замінює її тіло, не змінюючи викликачів. Облікові дані не виходять із серверної гілки
читання.»

**П2 — D36 п. 11, після «…і пропонує звузити період.»** Додати: «Межу зупинки конверт несе структурно —
полем `ПрочитанныйОтрезок` (початок і кінець охопленого до зупинки, київський час; додавання, версія 1).
Ставить його спільне ядро конекторів лише при стелі; напрям читання дає конектор. Інтерактив пропонує
людині решту періоду поза відрізком і читає її лише після підтвердження; регламент (5б) за відрізком
просуває курсор. Текст діагностики розбирати не треба й не можна.» Те саме одним реченням — у
`docs/architecture/connectors.md` §6 (задача 5).
