# Платформа завантаження виписок SMB — план блоку «Спрощення»

## 1. Шапка

- **Статус:** на прийманні архітектора (`smp-bankexchange-e1`). Автор — `smp-bankexchange-ab`, 2026-11-24.
- **Вхід:** findings — висновки архітектора smb-simplify-findings у гітігнорованій теці брифів `.agents`
  основного дерева (HEAD `810d1b4`; BSL на `f321c54` той самий). Незлитої роботи, від якої залежить план, немає.
- **Режим:** `shared`. Спільний рантайм — серверна база агента `SMP_BankExchange_SMB`; тримає один виконавець
  за раз, вікно дає архітектор; збирати лише source-set розширень (без `sourceSet` і `kit provision` — руйнівно).
- **Місце** призначає архітектор; Уніка мусить бачити `cf/src` (у `.worktrees/*` без неї —
  `workspace is uninitialized`, kit issue #141). Код 1С — лише Унікою, у брифах субагентів теж.
- **Прогін тестів (Unica 0.16):** `push` обох source-set, потім з теки воркспейсу `v8-runner … test --no-push
  yaxunit module <Модуль>` (повна команда — findings §8); `test` в `unica.run` немає.

## 2. Мета / Архітектура / Спека

**Мета.** Зменшити код і тести SMB до перемикання (ADR-0020) без зміни поведінки: дублювання й мертві
гілки (≈1 300 рядків після звірки; дослідження оцінювало ≈1 650–2 000), тести ≈1 500 → ≈100 (ADR-0018).
Головне — **спільне ядро конекторів**: на ньому пишуться NovaPay (5б-3) і регламент (5б).

**Архітектура.** Шари D28, D30, D36 лишаються. Спільне йде в наявні модулі шару (`СМП_КоннекторыБанковОбщее`,
`СМП_ЧтениеВыписокОбщее`, `СМП_ВыпискаБанка`, `СМП_ЗаписьДокументовБанка`); нових модулів немає.

**Спека** `docs/superpowers/specs/2026-10-12-smb-import-platform-design.md`: D28, D30, D31, D35.5,
D35.12, D36 п. 3, 4, 7, 8, 10, 11. ADR-0014, 0017, 0018, 0020. Правок спеки блок не потребує (розділ 4).

## 3. Глобальні обмеження

1. **Поведінка не змінюється**, крім названих рішень (розділ 4). «Не змінилась» = keep-модулі шару задачі
   зелені до й після задачі на закоміченому стані.
2. **Зелений прогін keep-модуля** = усе разом: `push` обох source-set без помилки (вивід — у журнал);
   ім'я модуля без префікса `CommonModule.`; exit 0; failed = 0; total = очікуваному total цього модуля з
   журналу (задача 0). total = 0, модуля чи рядка в журналі немає — червоне. Очікуваний total змінюється
   лише записом у журналі з причиною, який приймає архітектор.
3. **Покриття й мутація.** Кожна задача 2–7 до коду пише в журнал «група змін → keep-метод, що через неї
   проходить». Групу без такого методу покриває тимчасовий зонд (не комітиться) з критерієм червоного.
   Одна мутація на задачу: зламаний результат одного зміненого методу продукту → після `push` keep-модуль
   червоний → повернення → зелений; так доведено, що `push` доніс код і keep-шар дивиться.
4. **Нових постійних тестів немає.** Тест, що кличе метод за іменем і ламається від зняття `Экспорт`
   чи переїзду, правиться (нове ім'я) або видаляється, якщо він поза keep-набором. Keep-тест, переписаний
   у задачі разом з кодом, ганяється тричі: старий текст на старому коді — зелений; новий текст на новому
   коді — зелений; новий текст на мутації, яку тест має ловити, — червоний.
5. Сигнатури контракту лишаються: `ОписаниеЧитателя()`, `Прочитать(Данные, Параметры, Выписка) Экспорт`
   кожного формату й конектора, `ПрочитатьСРазмеромСтраницы` конекторів (тестові обгортки
   `СМП_ТестКоннекторРазмерСтраницы*`).
6. Курсор, період регламенту й перекриття — не в конекторі (ADR-0014). Ядро конектора їх не знає.
7. Після правки XML Унікою — звірити `git diff` побайтово (CRLF→LF, `&#13;`). У Form.xml
   `СМП_ОбменСБанком` не ставити `<Visible>false</Visible>` (зараз 0 у п'яти формах).
8. Журнал прогонів блоку — файл з іменем плану й суфіксом `-runs` поруч із планом, створює задача 0:
   кожен прогін — коміт, модуль, total/passed/failed, вивід `push`.
