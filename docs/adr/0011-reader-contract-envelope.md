# ADR-0011: Контракт читача — порожній конверт від платформи, лише типи платформи 1С

Status: accepted 2026-10-12
Decided by: owner
Spec: `docs/superpowers/specs/2026-10-12-smb-import-platform-design.md` §3 D27, D28; `docs/architecture/reader-contract.md`

## Context
Та сама обробка читання має працювати в УНФ українській, УНФ російській і бухгалтерії. Вбудовані
читачі, конектори API й сторонні обробки мають бути рівноправними джерелами.

## Decision
Контракт один для всіх джерел і конфігурацій: `ОписаниеЧитателя()` плюс `Прочитать(Данные, Параметры,
Выписка)`. Платформа створює порожній конверт, читач лише заповнює його фактами банку. Конверт
спирається лише на типи платформи 1С. Платформа на межі приймає чи відкидає конверт і нічого не
виправляє. Версія контракту росте лише додаванням колонок.

## Why
Вимога власника — один контракт для всіх конфігурацій. Вендор російської УНФ має схожу межу
(`НовыйВыпискаПоБанковскомуСчету`).

## Rejected
- XDTO — пакет мусив би лежати в метаданих кожного розширення.
- JSON — подвійна серіалізація, немає типу «дата».
- Типи конфігурації в конверті.

## Consequences
Читач не створює документів, не шукає контрагентів і не фільтрує чужі рахунки — це робить платформа.
Відхилений конверт ніколи не вважається повним для курсора.
