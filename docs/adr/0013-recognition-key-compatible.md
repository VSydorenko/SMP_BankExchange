# ADR-0013: Ключ впізнавання сумісний з попередником; виняток — ПУМБ з дати переходу

Status: accepted 2026-11-04
Decided by: owner
Spec: `docs/superpowers/specs/2026-10-12-smb-import-platform-design.md` §3 D17

## Context
Нова платформа читатиме періоди, які вже завантажила стара обробка. Якщо поля ключа заповнюються
інакше, «точніше значення» дає не покращення, а дублі. Попередник ПУМБ `СМП_ИДТранзакцииБанка` не писав.

## Decision
Ключ — ідентифікатор банку в `СМП_ИДТранзакцииБанка` (ADR-0004); без нього — складений ключ: день
`ДатаВходящегоДокумента`, `НомерВходящегоДокумента`, рахунок контрагента, сума. Для джерел із
попередником поля заповнюються так само, як у попередника. Збіг рахується кількісно: k операцій і m
документів дають min(k, m) зіставлень. ПУМБ — без сумісності: новий механізм вантажить з дати переходу,
яку обирає власник, і раніше неї регламент не читає.

## Why
У сумніві видимий дубль кращий за невидиму втрату. Власник про ПУМБ: «просто з дати починаємо грузити
по новому і все».

## Rejected
- Змінювати поля ключа без окремого рішення про дедуплікацію.
- Приводити правильне API ПУМБ до еталону старої обробки.

## Consequences
Кращі значення в полях ключа — «тюнінг», поза етапом і лише окремим рішенням.
