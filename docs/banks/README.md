# Банки

`epf/src/` — джерело правди для дванадцяти файлових обробок читання виписок (спільне для
всіх трьох продуктів через довідник «Дополнительные отчеты и обработки»; контракт обробки —
`docs/architecture/data-processor-contract.md`). Джерело таблиці — самі теки `epf/src/` і
функції `СведенияОВнешнейОбработке()`/`ФорматФайла()` кожної обробки.

Усі дванадцять — обробки **файлу** виписки (жодна не звертається до HTTP/API напряму — перевірено
пошуком `HTTPЗапрос`/`HTTPСоединение`/`WSПрокси`/`http(s)://` по `epf/src/*/Ext/ObjectModule.bsl`,
збігів немає). Банки з API-доступом (ПриватБанк, monobank, ПУМБ, NovaPay) підключені **не через
цей механізм**, а вбудовані прямо в розширення — див. `docs/architecture/overview.md`, розділ
«Як підключаються обробки читання форматів».

## Банки з доступом через API (поза цим списком)

Реалізовані прямо в розширенні (`CommonModules/СМП_РаботаСБанками<Банк>APIСервер`), без обробки
в `epf/`:

| Банк | Модуль | Протокол | Присутній у продуктах |
|---|---|---|---|
| monobank (ФОП) | `СМП_РаботаСБанкамиМонобанкAPIСервер` | REST, `api.monobank.ua` | `BankExchange_SMB`, `BankExchange_SMBru` |
| monobank (ТОВ) | `СМП_РаботаСБанкамиМонобанкЮрAPIСервер` | REST, `corp-api.monobank.ua` | `BankExchange_SMB` |
| ПриватБанк | `СМП_РаботаСБанкамиПриватБанкAPIСервер` | REST, `acp.privatbank.ua` (через `КоннекторHTTP_BankExchange`) | усі три |
| ПУМБ | `СМП_РаботаСБанкамиПУМБAPIСервер` | REST | усі три |
| NovaPay | `СМП_РаботаСБанкамиNovaPayAPIСервер` | SOAP/WSDL (`WSПрокси`) | `BankExchange_SMB` |

У monobank таких API **п'ять**, і вони несумісні: персональне (рахунки ФОП і фізосіб)
і окреме API юридичних осіб на іншому хості — звідси два режими нижче.
Межа «ФОП / ТОВ», відмінності схем і чому призначення платежу для ФОП недоступне —
`monobank-api-map.md`.

## monobank — два режими

| Режим | Значення переліку | Модуль | API |
|---|---|---|---|
| ФОП | `МОНОБанк` | `СМП_РаботаСБанкамиМонобанкAPIСервер` | персональне, `api.monobank.ua/personal` |
| ТОВ | `МОНОБанкЮр` | `СМП_РаботаСБанкамиМонобанкЮрAPIСервер` | юросіб, `corp-api.monobank.ua/ext/v1` |

Чому два — [monobank-api-map.md](monobank-api-map.md). Дизайн — `docs/superpowers/specs/2026-09-15-monobank-fop-tov-design.md`.

Дедуплікація обох режимів — за реквізитом `СМП_ИДТранзакцииБанка` документів `ПоступлениеНаСчет` / `РасходСоСчета`
(пошук у `СМП_КлиентБанк.РаспознатьДанныеВСтрокеДокумента`). Синхронізація-видалення: ФОП — вимкнена завжди,
ТОВ — лише за повної виписки і `isFinal` по всіх завантажених датах. Регламент іде від курсора
`СМП_НомерПоследнейТранзакции` (дата, день перечитується).

Формат API юросіб не підтверджено специфікацією (з машини агента `corp-api.monobank.ua` дає 403):
припущення A–D позначені коментарями в модулі ТОВ і перевіряються чеклістом Task 8 плану
`docs/superpowers/plans/2026-09-15-monobank-fop-tov.md`.

## Відомий дублікат (не джерело правди)

`BankExchange_SMB/cfe/src/DataProcessors/` тимчасово містить власну копію **усіх дванадцяти**
файлових обробок з `epf/src/` — жоден банк з `epf/src/` не пропущений (перевірено порівнянням
імен: `comm` між списком `epf/src/` і списком `DataProcessors/` не знаходить жодного банку,
присутнього лише в `epf/src/`). Додатково всередині є **тринадцята** обробка — `КредоБанк`,
якої в `epf/src/` немає взагалі. Тобто в розширенні тринадцять файлових обробок, у `epf/src/` —
дванадцять; зайва одна — саме `КредоБанк`.

Наслідок: `КредоБанк` наразі не має відповідника в `epf/` і тому лишається поза шляхом
підключення через довідник зовнішніх обробок, яким користуються решта банків.

Це історичний залишок до переходу на `epf/` як єдине джерело. Видалення заплановане окремою
задачею (Етап 5 дизайну перезапуску) і не входить у цю документацію.
