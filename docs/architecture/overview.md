# Підсистема BankExchange

## Що робить

Підсистема інтегрує конфігурації на платформі 1С:Підприємство/BAF з клієнт-банком: завантажує
банківські виписки (створюючи документи надходження/списання коштів) і, для частини банків,
вивантажує платіжні доручення назад у банк. Налаштування ведеться в розрізі **банківського
рахунку**, а не користувача — довідник `СМП_УчетныеЗаписиБанков` («Облікові записи банків»)
зберігає для кожного рахунку організації банк, спосіб доступу (файл чи API) і облікові дані.
Виписка завантажується за період, який зазначено в самому файлі виписки чи який повернув банк
через API — дату завантаження вказувати не потрібно.

Джерело цього опису — `README.md` кореня репозиторію і код нижче.

## Три розширення і чим відрізняються

Три продукти в корені репозиторію — це три розширення для трьох різних базових конфігурацій.
Спільне ядро (мовою коду, не назвою) — `Справочники.СМП_УчетныеЗаписиБанков` і
`CommonModules/СМП_РаботаСБанкамиСервер`; решта складу відрізняється залежно від того, що вміє
й чого потребує базова конфігурація.

| Продукт | Базова конфігурація | Обробка-точка входу | Що унікального |
|---|---|---|---|
| `BankExchange_SMB` | BAS small business (УНФ, **українська**) | `DataProcessors/СМП_КлиентБанк` | Повний набір API-банків (NovaPay, monobank, ПриватБанк, ПУМБ); модуль генерації TOTP (`СМП_ГенерацияTOTPСервер`) для 2FA; механізм прямого обміну електронними документами (`ОбменСБанками*`, borrowed/перевизначений); тимчасово — внутрішня копія всіх 12 файлових обробок з `epf/` плюс тринадцята, `КредоБанк`, якої в `epf/` немає (усі 13 як `DataProcessors`, деталі — `docs/banks/README.md`; план — прибрати, див. «Поза обсягом» у дизайні перезапуску) |
| `BankExchange_SMBru` | BAS small business (УНФ, **російська**) | `DataProcessors/СМП_КлиентБанк` | Той самий контур без NovaPay, без TOTP і без внутрішньої копії файлових обробок — файлові банки підключаються тільки через довідник `ДополнительныеОтчетыИОбработки` з `epf/` |
| `BankExchange_ACC` | BAS for accounting (бухгалтерія, **українська**) | `DataProcessors/КлиентБанк` (без префікса `СМП_`) | Немає NovaPay і monobank (тільки ПриватБанк і ПУМБ через API); власний довідник відповідності призначень платежу й реквізитів (`СМП_СоответствияНазначенийИРеквизитовПлатежа`); журнал документів «Деньги»; документи-ордери (`ПлатежныйОрдерПоступлениеДенежныхСредств`/`...Списание...`) замість документів УНФ |

Перевірено переліком `CommonModules`/`Documents`/`Catalogs` кожного продукту
(`BankExchange_SMB/cfe/src`, `BankExchange_SMBru/cfe/src`, `BankExchange_ACC/cfe/src`) — не
з опису плану.

Іменування об'єктів послідовне: нові об'єкти підсистеми мають префікс `СМП_`
(`Справочники.СМП_УчетныеЗаписиБанков`, `Подсистема.СМП_BankExchange`, `CommonModules/СМП_*`).
Об'єкти без префікса (`КлиентБанкВызовСервера`, `УправлениеНебольшойФирмойКлиент`,
`ОбменСБанками`, `КлиентБанк` в ACC) — це **запозичені** (borrowed) об'єкти базової конфігурації,
де розширення перехоплює чи доповнює існуючу поведінку; їм лишають оригінальне ім'я, бо саме за
ним Unica (`cfe.borrow`) і платформа встановлюють зв'язок з об'єктом-власником.

## Склад розширення

На прикладі `BankExchange_SMB/cfe/src` (найповніший набір):

| CommonModule | За що відповідає |
|---|---|
| `КлиентБанкВызовСервера` | Запозичений виклик сервера форми клієнт-банку; містить `СМП_ПолучитьОбработкуПротокола` — пошук обробки читання формату для конкретного банківського рахунку |
| `КоннекторHTTP_BankExchange` | Сторонній відкритий HTTP-клієнт «Коннектор» (Vladimir Bondarevskiy, Apache-2.0), запозичений як бібліотека для звернень до банківських API |
| `ОбменСБанками`, `ОбменСБанкамиКлиент`, `ОбменСБанкамиКлиентСервер`, `ОбменСБанкамиПереопределяемый` | Запозичений/перевизначений механізм прямого обміну електронними документами з банком (1С:ДиректБанк) |
| `СМП_ГенерацияTOTPСервер` | Генерація TOTP-кодів (RFC 6238) для банків з двофакторною автентифікацією через API |
| `СМП_РаботаСБанкамиNovaPayAPIСервер` | Інтеграція з NovaPay через SOAP/WSDL (`WSПрокси`) |
| `СМП_РаботаСБанкамиМонобанкAPIСервер` | Інтеграція з monobank через REST API (`api.monobank.ua`) |
| `СМП_РаботаСБанкамиПриватБанкAPIСервер` | Інтеграція з ПриватБанк через REST API (`acp.privatbank.ua`), поверх `КоннекторHTTP_BankExchange` |
| `СМП_РаботаСБанкамиПУМБAPIСервер` | Інтеграція з ПУМБ через API |
| `СМП_РаботаСБанкамиСервер` | Спільні службові процедури підсистеми (перевірка функціоналу банку тощо) |
| `УправлениеНебольшойФирмойКлиент` | Запозичений клієнтський модуль УНФ; перехоплює `ЗагрузитьДанныеИзФайлаВыписки` |
| `ЭлектронноеВзаимодействиеКлиентПереопределяемый` | Запозичений/перевизначений модуль обробки помилок електронної взаємодії |

Заміщені/доповнені об'єкти конфігурації: довідник `СМП_УчетныеЗаписиБанков` (облікові записи
банків — новий об'єкт), інформаційний регістр `ИсторияРаботыСКлиентомБанка`, документ
`ПоступлениеНаСчет` (запозичений — доповнюється реквізитами обміну), підсистема
`СМП_BankExchange` (командний інтерфейс).

**Точка входу** — обробка `DataProcessors/СМП_КлиентБанк` (в ACC — `DataProcessors/КлиентБанк`).
Її `ObjectModule.bsl` (2661 рядок) і `ManagerModule.bsl` (6044 рядки) містять форми взаємодії з
користувачем (`ФормаЗагрузка`, `ФормаВыгрузка`, `ФормаНастройка`, `ФормаСтарт` та інші) і спільні
службові функції розбору виписки (`СформироватьСоответствиеЗагружаемых`,
`РаспознатьДанныеВСтрокеДокумента`, `ПроверитьНаПустоеЗначениеИмпорта`, `СписокНеНайденных` —
усі в `ManagerModule.bsl`), якими користуються зовнішні обробки читання форматів (див.
`docs/architecture/data-processor-contract.md`).

## Як підключаються обробки читання форматів

Кожен банківський рахунок в довіднику `СМП_УчетныеЗаписиБанков` посилається на банк
(`Перечисление.СМП_ПоддерживаемыеИнтеграцииСБанками` чи довідник `КлассификаторБанков` — залежно
від продукту) і, за потреби, на конкретну підключену обробку через реквізит
`ПодключаемаяОбработка` (тип `СправочникСсылка.ДополнительныеОтчетыИОбработки` — стандартний
довідник БСП «Дополнительные отчеты и обработки»).

Ланцюжок виклику (простежено в
`DataProcessors/СМП_КлиентБанк/Forms/ФормаЗагрузка/Ext/Form/Module.bsl`):

1. `КлиентБанкВызовСервера.СМП_ПолучитьОбработкуПротокола(БанковскийСчет)` — запитом знаходить
   елемент `СМП_УчетныеЗаписиБанков` за банківським рахунком і повертає або сам елемент (якщо
   банк не потребує окремої обробки), або значення `ПодключаемаяОбработка`.
2. Форма зчитує бінарні дані обробки з реквізиту `ХранилищеОбработки` цього елемента довідника
   (`ХранилищеОбработки.Получить()`), записує їх у тимчасовий `.epf`-файл.
3. `ВнешниеОбработки.Создать(ИмяФайла, Ложь)` створює екземпляр обробки з файлу.
4. Викликається її експортна процедура `Загрузить_УНФ(ЭтаФорма, ИмяВременногоФайла,
   ТаблицаТаблицДокументов, ТаблицаКонтрагентов)` — контракт описано в
   `docs/architecture/data-processor-contract.md`.

Для банків з API (NovaPay, monobank, ПриватБанк, ПУМБ) цей ланцюжок не використовується:
натомість викликається `Справочники.СМП_УчетныеЗаписиБанков.ЗагрузитьВыпискуЧерезAPI(...)`, яка
напряму звертається до відповідного `CommonModules/СМП_РаботаСБанками<Банк>APIСервер`. Тобто
модель підключення двонаправлена за типом джерела: файлові формати — через довідник зовнішніх
обробок (`epf/`, «джерело правди» для 12 банків), API — вбудовані безпосередньо в розширення.
