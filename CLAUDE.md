# SMP_BankExchange — інструкції проєкту

Підсистема обміну з клієнт-банком для конфігурацій на платформі 1С:Підприємство / BAF:
три розширення під різні конфігурації плюс зовнішні обробки читання форматів виписок.

## Продукти

| Воркспейс | Що це | Ім'я розширення в 1С | Сховище |
|---|---|---|---|
| `SMP_BankExchange_SMB` | BAS small business — **УНФ, українська** | `SMP_BankExchange_SMB` | `СМП_BankExchange_SMB` |
| `SMP_BankExchange_SMBru` | **УНФ, російська** | `SMP_BankExchange_SMBru` | `СМП_BankExchange_SMBru` |
| `SMP_BankExchange_ACC` | BAS for accounting — українська бухгалтерія | `SMP_BankExchange_ACC` | `СМП_BankExchange_BP` |
| `epf` | 12 обробок читання форматів виписок (`truth: git`) | — | — |

Дві пастки в іменуванні, обидві історичні й обидві очікувані:

- тека сховища ACC зветься **`_BP`**, а розширення — **`_ACC`**. Це не помилка маніфесту:
  ключ джерела береться з імені розширення, шлях — зі `storagePath`;
- у **старому** дереві (до тега `legacy/gitsync-2025-02`) тека `SMB` означала *російську*
  УНФ, а `BAS small business` — *українську*. Нові назви збігаються з іменем розширення
  в Конфігураторі, тому читаються прямо.

## Робочі копії й тимчасові файли

Робочі копії й тимчасові файли — лише в гітігнорованих теках проєкту, не в системному temp, не в теці
сесії Claude Code і не в теках поруч із репозиторієм: робоча копія задачі — `.worktrees/` (`pr-gate start`
чи `git worktree add .worktrees/<ім'я>`), разова — `pr-gate scratch add`; вивід, скрипти, тимчасові файли —
`.agents/out/`; брифи — тека `briefs` у `.agents/`; чужі матеріали дослідження — `temp/`.

## Межі

- **Репозиторій може бути публічним.** Секрети й локальні шляхи — лише у гітігнорованих
  `v8storagekit.local.yaml` і `v8project.local.yaml`. База агента й її пароль — лише в
  гітігнорованому `v8project.local.yaml`. Шлях сховища у маніфесті — свідомий виняток.
- Платформа цієї машини — `C:\Program Files\1cv8\8.3.27.1644\bin\1cv8.exe`. EDT у проєкті не
  використовується.
- Матеріали дослідження — чужі специфікації API, експорти чатів і подібне — кладемо в гітігноровану
  `temp/`, а не в `docs/`: репозиторій публічний, а експорт телеграм-чату, приміром, містить імена
  реальних людей. У `docs/` іде лише висновок, написаний своїми словами, з цитатами рівно тієї
  довжини, яка потрібна.
- Жодних `ConfigurationRepositoryCommit`/`Lock`/`UnlockObjects`.
- Файли ліцензій 1С теж не чіпати.

## Робота через Unica — специфіка проєкту

Запозичення (`unica.apply`, `object.borrow`) і різниця розширення з конфігурацією (`unica.diff`)
потребують вивантаженої `cf/src` — це `v8storagekit:infobase-dump`. Для правок коду й форм уже
запозичених об'єктів вона не обов'язкова. Без `cf/src` розширення в базу агента не стане:
більшість його об'єктів — запозичені.

**Збірка `.cfe`:** `unica.run {"op":"make","args":{"sourceSet":"<Ім'я>","extension":"<Ім'я>","output":"build/artifacts/<Ім'я>.cfe"},"dryRun":true}` — шлях
`output` **відносний до воркспейсу**, бо поза свій корінь Уніка писати відмовляється. Файл лягає у
`<Воркспейс>/build/artifacts/`; `.epf`/`.erf` збирає той самий `make`. Kit файлів не копіює й
не перейменовує.

**Збірка `.cf`** основної конфігурації — так само, поруч із `.cfe`. Людина в сховищі робить
«Порівняти, об'єднати з конфігурацією з файлу», а **не** завантажує `.cf` цілком: це замінило б
усю конфігурацію разом із поставкою й вимагало б захоплення всього сховища.

Кеш Unica `.build/unica` створюється поруч із кожним використаним коренем — він у
`.gitignore` без провідного слеша, щоб ловився на всіх рівнях.

**Перевіряти збірку за датами файлів, а не за їх наявністю:** `build/artifacts/` між прогонами не
чиститься, тож давній артефакт поруч зі свіжими виглядає як щойно зібраний.

**Виняток — воркспейс `SMP_BankExchange_SMB`:** його база агента серверна й спільна (накладка
`v8project.local.yaml`), там `kit provision` і збірка без `sourceSet` руйнівні, а тести YaXUnit
живуть в окремому розширенні `SMP_BankExchange_SMB_Tests` (`tests/src`). Як збирати й
проганяти тести — `docs/known-state.md`, розділ «База агента SMB».

## Історія до переходу на v8storagekit (межа 2025-02)

Репозиторій до лютого 2025 вивантажувався зі сховищ старим інструментом (gitsync),
і вихідники лежали в **EDT-форматі** за іншими шляхами. 2026-09-10 перехід повторено
від останньої чистої gitsync-точки: шляхи перенесено `kit rename-edt`, вміст замінено
дампом зі сховища. Тому історія **безперервна** — але деякі запити потребують прапорця.

Межа: тег `legacy/gitsync-2025-02` (коміт `dca2f8a`, 2025-02-24).

Відповідність шляхів через межу:

| Було (EDT, до межі) | Стало (Designer) |
|---|---|
| `BAS small business/src/` | `SMP_BankExchange_SMB/cfe/src/` |
| `BAS for accounting/src/` | `SMP_BankExchange_ACC/cfe/src/` |
| `SMB/src/` | `SMP_BankExchange_SMBru/cfe/src/` |
| `ExtDataProcessors/<Банк>/src/` | `epf/src/` |
| `<Об'єкт>/<Об'єкт>.mdo` | `<Об'єкт>.xml` |
| `<Об'єкт>/Forms/<Форма>/Form.form` | `<Об'єкт>/Forms/<Форма>/Ext/Form.xml` |
| `<Об'єкт>/ManagerModule.bsl` | `<Об'єкт>/Ext/ManagerModule.bsl` |
| `<Роль>/Rights.rights` | `<Роль>/Ext/Rights.xml` |

Як діставати історію:

```bash
git log --follow -- <шлях>          # ОБОВ'ЯЗКОВО --follow: без нього видно лише коміти після межі
git blame -w -- <шлях>              # -w знімає розбіжності в пробілах; для BSL працює через межу
git show legacy/gitsync-2025-02:'BAS small business/src/<шлях>'   # прочитати файл до межі
```

Коміти конверсії перелічені в `.git-blame-ignore-revs` — увімкнути одноразово:
`git config blame.ignoreRevsFile .git-blame-ignore-revs`.
