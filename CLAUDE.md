# SMP_BankExchange — інструкції проєкту

Підсистема обміну з клієнт-банком для конфігурацій на платформі 1С:Підприємство / BAF:
три розширення під різні конфігурації плюс зовнішні обробки читання форматів виписок.

Репозиторій працює під плагіном Claude Code `v8storagekit`
(https://github.com/VSydorenko/SMP_V8StorageKit): сховища конфігурацій 1С — істина, git —
робоче середовище агента, Unica — основний інструмент. На старті сесії хук плагіна показує «Стан
сховищ» і вступ `using-v8storagekit`; далі — скіли по одному на намір.

**Сесію Claude Code відкривати в корені цього репозиторію.** Уніка бачить лише теки сесії, а
воркспейси — підтеки кореня; сесія в підтеці бачить лише її (хук попередить). Тека поза сесією —
`v8storagekit:unica-folders`.

## Продукти

| Воркспейс | Що це | Ім'я розширення в 1С | Сховище |
|---|---|---|---|
| `SMP_BankExchange_SMB` | BAS small business — **УНФ, українська** | `SMP_BankExchange_SMB` | `СМП_BankExchange_SMB` |
| `SMP_BankExchange_SMBru` | **УНФ, російська** | `SMP_BankExchange_SMBru` | `СМП_BankExchange_SMBru` |
| `SMP_BankExchange_ACC` | BAS for accounting — українська бухгалтерія | `SMP_BankExchange_ACC` | `СМП_BankExchange_BP` |
| `epf` | 12 обробок читання форматів виписок (`truth: git`) | — | — |

Дві пастки в іменуванні, обидві історичні й обидві очікувані:

- тека сховища ACC зветься **`_BP`**, а розширення — **`_ACC`**. Це не помилка маніфесту:
  ключ джерела береться з імені розширення, шлях — зі `storagePath`;
- у **старому** дереві (до тега `legacy/gitsync-2025-02`) тека `SMB` означала *російську*
  УНФ, а `BAS small business` — *українську*. Нові назви збігаються з іменем розширення
  в Конфігураторі, тому читаються прямо.

## Структура

| Що | Де |
|---|---|
| Маніфест kit: воркспейси, джерела, `truth`, сховища | `v8storagekit.yaml` (корінь) |
| Локальне цієї машини: дев-бази, шляхи сховищ, шаблон `.dt` бази агента | `v8storagekit.local.yaml` (гітігнорований) |
| Воркспейс Уніки: source-set-и, `providers` (`designer` — інваріант контуру) | `<Воркспейс>/v8project.yaml` |
| База агента — `infobases.origin` (`connection`, `user`, `password`); пише скіл `v8storagekit:provision` | `<Воркспейс>/v8project.local.yaml` (гітігнорований, файл Уніки) |
| Вихідники платформи | `<Воркспейс>/<тип>/src` — шляхи з `v8project.yaml`; `truth: vendor` у git не потрапляє |
| Дзеркала сховищ | гілки `storage/<джерело>` — пише лише `kit sync` |
| Артефакти для людини | `<Воркспейс>/build/artifacts/` (збирає `make` Уніки; гітігноровано) |
| Мапа «користувач сховища → git-автор» | `AUTHORS` |
| Робочі матеріали дослідження | `temp/` (гітігноровано) — чужі специфікації, експорти чатів, чернетки |
| Архітектура підсистеми, контракт обробки, по банках | `docs/architecture/`, `docs/banks/` |
| **Базові лінії інструментів** — що вважати нормою у виводі | `docs/known-state.md` |

Воркспейси й джерела: `pwsh -NoProfile -File "<корінь плагіна>/tools/kit.ps1" check -RepoRoot .`
(перший рядок `[i]`). Корінь плагіна показує `claude plugin list`.

## Гілки

`main` — історія проєкту: злиття PR-ів і звірочні коміти. `storage/<джерело>` — дзеркало
сховища, лише дописується. `feature/<задача>` — гілка агента від головної; прийняття версії
сховища заміною піддерева (`adopt`) — `v8storagekit:reconcile`; PR — `v8storagekit:finish`.
Реплей у головну гілку не йде.

Заміна, а не злиття, — свідомо: людина кладе у сховище свою версію, можливо взявши лише частину
роботи агента, і merge лишив би в гілці те, чого вона не взяла; прев'ю `adopt` показує
заздалегідь, що прийде зі сховища і що зникне з гілки.

## Наміри → скіли

| Намір | Скіл |
|---|---|
| нові версії у сховищі → git | `v8storagekit:sync` |
| вивантажити з бази людини (`truth: dump`/`vendor`) | `v8storagekit:dump` |
| людина перенесла частину в сховище | `v8storagekit:reconcile` |
| закрити задачу, PR | `v8storagekit:finish` |
| база агента | `v8storagekit:provision` |
| звірити git зі сховищем | `v8storagekit:verify` |
| додати воркспейс/джерело | `v8storagekit:onboarding` |
| Уніка не бачить потрібної теки | `v8storagekit:unica-folders` |

Редагування (`unica.apply`), перевірка (`unica.check`), завантаження в базу агента й збірка
(`unica.run`) — Unica 0.16; маршрутизація — `v8storagekit:using-v8storagekit`.

**Збірка `.cfe`:** `unica.run {"op":"make","args":{"sourceSet":"<Ім'я>","extension":"<Ім'я>","output":"build/artifacts/<Ім'я>.cfe"},"dryRun":true}` — шлях
`output` **відносний до воркспейсу**, бо поза свій корінь Уніка писати відмовляється. Файл лягає у
`<Воркспейс>/build/artifacts/`; `.epf`/`.erf` збирає той самий `make`. Kit файлів не копіює й
не перейменовує.

**Збірка `.cf`** основної конфігурації — так само, поруч із `.cfe`. Людина в сховищі робить
«Порівняти, об'єднати з конфігурацією з файлу», а **не** завантажує `.cf` цілком: це замінило б
усю конфігурацію разом із поставкою й вимагало б захоплення всього сховища.

**`push` Уніки без `sourceSet` вантажить усі оголошені набори воркспейсу.** На серверній базі
агента — лише з явного підтвердження людини; для правок розширення — `sourceSet` цього розширення.
Після команд kit, що зрушили базу (`sync`, `verify`), — крок, який вони надрукували: `push` з
`"force":true`. Уніка спитає людину про перезапис бази — це очікувано; крок виконується лише в
інтерактивній сесії, відповідь `cancelled` — зупинка з доповіддю (`v8storagekit:using-v8storagekit`).

## Межі

- **Формат вихідників — Designer platform XML; платформа — гілка 8.3.27.x.**
- **Кінці рядків вихідників — `-text` у `.gitattributes`, політика kit.** Пораду `unica.check {}`
  (`git.text_resource_marked_binary`) замінити `-text` на `text eol=lf` не виконувати: на `ready` і
  допуск операцій Уніки вона не впливає, а змінює політику лише людина.
- **Репозиторій може бути публічним.** Секрети й локальні шляхи — лише у гітігнорованих
  `v8storagekit.local.yaml` і `v8project.local.yaml`. База агента й її пароль — лише в
  гітігнорованому `v8project.local.yaml`. Шлях сховища у маніфесті — свідомий виняток.
- **`truth: vendor` ніколи не комітиться** — код вендора.
- **Сховища — тільки читання.** Запис у сховище виконує людина в Конфігураторі. Гілки `storage/*`
  руками не редагуються — хук відмовить.
- **Агент працює у своїй базі й ніколи не пише в базу людини.** Базу людини kit лише читає
  (`dump`), і лише на явне прохання.
- **`-Apply` — лише на явне прохання.** `sync` і `verify` без `-Apply` усе одно піднімають
  платформу (хвилина-дві, ліцензія) — але нічого не змінюють. `dump` — **ні**: без `-Apply` він
  лише друкує базу, користувача й ціль.
- **Ліцензія 1С.** Підрядки `лиценз`, `ліценз`, `license`, `HASP` у виводі платформи — зупинка й
  доповідь; служби, реєстр, `nethasp.ini` не чіпати.
- **`git push`, `gh pr create` — лише за явним проханням** (у `.claude/settings.json` — `ask`).
- Платформа цієї машини — `C:\Program Files\1cv8\8.3.27.1644\bin\1cv8.exe`. EDT у проєкті не
  використовується.
- Матеріали дослідження — чужі специфікації API, експорти чатів і подібне — кладемо в гітігноровану
  `temp/`, а не в `docs/`: репозиторій публічний, а експорт телеграм-чату, приміром, містить імена
  реальних людей. У `docs/` іде лише висновок, написаний своїми словами, з цитатами рівно тієї
  довжини, яка потрібна.
- Жодних `ConfigurationRepositoryCommit`/`Lock`/`UnlockObjects`.
- Файли ліцензій 1С теж не чіпати.

## Дозволи

`.claude/settings.json` дозволяє без запиту лише читання git, читальні інструменти Unica і
`unica_run` (перелік — `permissions.allow` у `.claude/settings.json`): перезапис бази агента
однаково підтверджує людина у питанні самої Уніки. `unica_apply` — з запитом (`permissions.ask`).
Хук `SessionStart` поставляє сам плагін. Команди kit — з підтвердженням
(правила дозволів працюють за префіксом, і дозвіл на прев'ю дозволив би `-Apply`).

## Робота через Unica — специфіка проєкту

Запозичення (`unica.apply`, `object.borrow`) і різниця розширення з конфігурацією (`unica.diff`)
потребують вивантаженої `cf/src` — це `v8storagekit:dump`. Для правок коду й форм уже
запозичених об'єктів вона не обов'язкова. Без `cf/src` розширення в базу агента не стане:
більшість його об'єктів — запозичені.

Кеш Unica `.build/unica` створюється поруч із кожним використаним коренем — він у
`.gitignore` без провідного слеша, щоб ловився на всіх рівнях.

**Перевіряти збірку за датами файлів, а не за їх наявністю:** `build/artifacts/` між прогонами не
чиститься, тож давній артефакт поруч зі свіжими виглядає як щойно зібраний.

**Виняток — воркспейс `SMP_BankExchange_SMB`:** його база агента серверна й спільна (накладка
`v8project.local.yaml`), там `kit provision` і збірка без `sourceSet` руйнівні, а тести YaXUnit
живуть в окремому розширенні `SMP_BankExchange_SMB_Tests` (`tests/src`). Як збирати й
проганяти тести — `docs/known-state.md`, розділ «База агента SMB».

## Історія до переходу на v8storagekit (межа 2025-02)

Репозиторій до лютого 2025 вивантажувався зі сховищ старим інструментом (gitsync),
і вихідники лежали в **EDT-форматі** за іншими шляхами. 2026-09-10 перехід повторено
від останньої чистої gitsync-точки: шляхи перенесено `kit rename-edt`, вміст замінено
дампом зі сховища. Тому історія **безперервна** — але деякі запити потребують прапорця.

Межа: тег `legacy/gitsync-2025-02` (коміт `dca2f8a`, 2025-02-24).

Відповідність шляхів через межу:

| Було (EDT, до межі) | Стало (Designer) |
|---|---|
| `BAS small business/src/` | `SMP_BankExchange_SMB/cfe/src/` |
| `BAS for accounting/src/` | `SMP_BankExchange_ACC/cfe/src/` |
| `SMB/src/` | `SMP_BankExchange_SMBru/cfe/src/` |
| `ExtDataProcessors/<Банк>/src/` | `epf/src/` |
| `<Об'єкт>/<Об'єкт>.mdo` | `<Об'єкт>.xml` |
| `<Об'єкт>/Forms/<Форма>/Form.form` | `<Об'єкт>/Forms/<Форма>/Ext/Form.xml` |
| `<Об'єкт>/ManagerModule.bsl` | `<Об'єкт>/Ext/ManagerModule.bsl` |
| `<Роль>/Rights.rights` | `<Роль>/Ext/Rights.xml` |

Як діставати історію:

```bash
git log --follow -- <шлях>          # ОБОВ'ЯЗКОВО --follow: без нього видно лише коміти після межі
git blame -w -- <шлях>              # -w знімає розбіжності в пробілах; для BSL працює через межу
git show legacy/gitsync-2025-02:'BAS small business/src/<шлях>'   # прочитати файл до межі
```

Перевірено на `SMP_BankExchange_SMB/.../СМП_КлиентБанк/Ext/ObjectModule.bsl`:
`--follow` дає 4 коміти проти 2 без нього, а `blame -w` приписує **2657 із 2661 рядка**
комітам 2024 року, тобто з-за межі.

Коміти конверсії перелічені в `.git-blame-ignore-revs` — увімкнути одноразово:
`git config blame.ignoreRevsFile .git-blame-ignore-revs`.
