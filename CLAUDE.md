# SMP_BankExchange — інструкції проєкту

Підсистема обміну з клієнт-банком для конфігурацій на платформі 1С:Підприємство / BAF:
три розширення під різні конфігурації плюс зовнішні обробки читання форматів виписок.

Дизайн і план перезапуску — `docs/superpowers/specs/2026-08-28-bankexchange-restart-design.md`
та `docs/superpowers/plans/2026-08-28-bankexchange-restart.md`.

## Структура

| Тека | Що це | Ім'я розширення в 1С |
|---|---|---|
| `BankExchange_SMB/` | BAS small business — **УНФ, українська** версія | `SMP_BankExchange_SMB` |
| `BankExchange_SMBru/` | **УНФ, російська** версія | `SMP_BankExchange_SMBru` |
| `BankExchange_ACC/` | BAS for accounting — українська бухгалтерія | `SMP_BankExchange_ACC` |
| `epf/` | 12 обробок читання форматів виписок | — |

Усередині продукту:

```
BankExchange_SMB/
├─ cfe/src/            вихідники розширення, Designer platform XML — у git
├─ cf/                 базова конфігурація — gitignored, вивантажується локально
│  └─ README.md        єдиний закомічений файл
├─ v8project.yaml      воркспейс Unica: cf(CONFIGURATION) + cfe(EXTENSION)
├─ v8project.local.yaml  gitignored: підключення й логіни
├─ storage.json        сховище, ім'я розширення, остання залита версія
└─ build/              gitignored
```

Не переплутай: у **старій** структурі тека `SMB` означала *російську* УНФ, а
`BAS small business` — *українську*. Нові назви збігаються з іменем розширення в
Конфігураторі, тому читаються прямо.

## Межі

- **Формат вихідників — тільки Designer platform XML.** EDT у проєкті більше не
  використовується: Unica його не редагує.
- **Платформа — тільки гілка 8.3.27.x** (`C:\Program Files\1cv8\8.3.27.1644\bin\1cv8.exe`).
  Unica інші гілки не підтримує; сховища створені саме цією версією.
- **Репозиторій публічний.** Рядки підключення до баз, імена серверів 1С, логіни та паролі
  **не потрапляють у закомічені файли** — тільки у `v8project.local.yaml` (gitignored) і в
  пам'ять проєкту. Перед пушем перевіряй `git log -p` на ці рядки; готова команда — у плані,
  Task 13. Єдиний свідомий виняток — шлях до каталогу сховища конфігурацій (`storagePath` у
  кожному `storage.json`, закомічений навмисно): синхронізація має бути самоналаштовуваною, а
  шлях сам собою не дає доступу ні до чого, на відміну від логіна й пароля. Деталі —
  `docs/architecture/storage-and-git.md`.
- **`cf/` ніколи не комітиться** — це код вендора, ліцензія цього не дозволяє.
- **Сховища конфігурацій — тільки читання.** Жодних `ConfigurationRepositoryCommit`,
  `ConfigurationRepositoryLock`, `ConfigurationRepositoryUnlockObjects`. Запис у сховище
  виконує людина в Конфігураторі.
- **Мутуючі скрипти без `-Apply` нічого не змінюють.** Ставити `-Apply` лише коли
  користувач явно попросив виконати.
- **Ліцензія 1С.** Якщо у виводі платформи трапилось `лиценз`, `license`, `HASP`,
  `No license` — зупинись і скажи користувачу. Не чіпай служби, реєстр, `nethasp.ini`,
  файли ліцензій.

## Типові операції

```powershell
pwsh tools/storage-sync.ps1 -Product BankExchange_SMB          # перегляд нових версій сховища
pwsh tools/storage-sync.ps1 -Product BankExchange_SMB -Apply   # перенести їх у git
pwsh tools/dump-config.ps1  -Product BankExchange_SMB -Apply   # вивантажити базову конфігурацію
pwsh tools/load-ext.ps1     -Product BankExchange_SMB -Apply   # розкотити вихідники в дев-базу
pwsh tools/build.ps1        -Apply                             # зібрати .cfe та .epf
pwsh tools/tests/Run-Tests.ps1                                 # тести інструментів
```

## Дозволи

`.claude/settings.json` дозволяє без запиту лише читання: git-команди перегляду, прогін тестів
і read-only інструменти Unica (`*.info`, `*.validate`, `code.*`, `source.*`, `project.*`).

Свідомо **не** в дозволених — запуски `storage-sync`, `dump-config`, `load-ext`, `build`. Правила
дозволів працюють за префіксом, тому дозвіл на попередній перегляд автоматично дозволив би й той
самий рядок із `-Apply` — а це вже запис у git і в базу. Хай запитує.

`gitsync` і `oscript` заборонені: старий контур замінено, і їхній запуск лише створив би
конкурентну історію. `git push`, `gh pr create`, `gh release` — завжди з підтвердженням.

## Робота через Unica

**Воркспейс — тека продукту, не корінь репозиторію.** Автоскан Unica обходить усе дерево
від `cwd` і падає на першому не-UTF-8 файлі; вузький корінь заодно тримає BSL-індекс малим.

Обмеження, які визначають маршрут (перевірено на цій машині):

- напрямок «база → git» (`dump`) в Unica на Windows **fail-closed** — вивантажує
  Конфігуратор через `tools/`;
- `make` для `.epf`/`.cfe` на Windows падає на публікації артефакту
  (`Отказано в доступе, os error 5`) — збирає `tools/build.ps1`;
- `cfe.borrow` і `cfe.diff` потребують вивантаженої `cf/src`;
- `convert` (Designer ↔ EDT) — applied fail-closed, доступний тільки `dryRun`.

Кеш Unica `.build/unica` створюється поруч із кожним використаним коренем — він у
`.gitignore` без провідного слеша, щоб ловився на всіх рівнях.

## Особливості платформи, на яких легко втратити час

Здобуто розвідкою 2026-08-28, усе перевірено фактично на цих сховищах.

- **`-Extension <Ім'я>` належить команді-дії**, а не `/ConfigurationRepositoryF`:
  `/ConfigurationRepositoryReport`, `/ConfigurationRepositoryUpdateCfg`,
  `/DumpConfigToFiles`, `/LoadConfigFromFiles`. Інакше — «Соединение основной
  конфигурации с хранилищем расширений конфигураций невозможно».
- **Розширення має існувати в ІБ до звернення до сховища розширень.** У порожній базі
  спершу `/LoadConfigFromFiles tools/assets/empty-extension -Extension <Ім'я>`; внутрішнє
  ім'я стаба ролі не грає — розширення створюється під тим, що в ключі. Без цього —
  «расширение конфигурации с указанным именем не найдено».
- **Запускати платформу тільки через `Start-Process` з готовим рядком аргументів.**
  Нативний виклик PowerShell псує лапки. `/IBConnectionString` вимагає подвоєних лапок
  усередині, тому використовуй `/F "<шлях>"` для файлових ІБ і `/S "<сервер>\<база>"`
  для серверних — вкладених лапок немає взагалі.
- **Кириличні шляхи не вшивати в `.cmd`-обгортки** — вони читаються в OEM-кодуванні й
  шлях ламається («хранилище не обнаружено»). Передавати аргументами або працювати з
  PowerShell напряму.
- **Звіт сховища — це MXL**, не текст: бінарна сигнатура `MOXCEL`, далі BOM і рядки
  `{"#","значення"}`. Мітки й величини йдуть парами; коментар буває багаторядковим,
  лапки всередині подвоєні. Розбирає `tools/lib/StorageReport.psm1`.
- **`/DumpConfigToFiles` не видаляє зниклі об'єкти** — цільову теку треба очищати перед
  кожним вивантаженням, інакше в дереві накопичується сміття з попередніх версій.
- **`$args` — автоматична змінна PowerShell.** Не називати так власні масиви аргументів.
