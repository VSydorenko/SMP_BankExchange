# SMP_BankExchange — інструкції проєкту

Підсистема обміну з клієнт-банком для конфігурацій на платформі 1С:Підприємство / BAF:
три розширення під різні конфігурації плюс зовнішні обробки читання форматів виписок.

Репозиторій працює під плагіном Claude Code `v8storagekit`
(https://github.com/VSydorenko/SMP_V8StorageKit): сховища конфігурацій 1С — істина, git —
робоче середовище агента, Unica — основний інструмент. На старті сесії хук показує «Стан
сховищ» і вступ `using-v8storagekit`; далі — скіли по одному на намір.

## Продукти

| Воркспейс | Що це | Ім'я розширення в 1С | Сховище |
|---|---|---|---|
| `SMP_BankExchange_SMB` | BAS small business — **УНФ, українська** | `SMP_BankExchange_SMB` | `СМП_BankExchange_SMB` |
| `SMP_BankExchange_SMBru` | **УНФ, російська** | `SMP_BankExchange_SMBru` | `СМП_BankExchange_SMBru` |
| `SMP_BankExchange_ACC` | BAS for accounting — українська бухгалтерія | `SMP_BankExchange_ACC` | `СМП_BankExchange_BP` |
| `epf` | 12 обробок читання форматів виписок (`truth: git`) | — | — |

Дві пастки в іменуванні, обидві історичні й обидві очікувані:

- тека сховища ACC зветься **`_BP`**, а розширення — **`_ACC`**. Це не помилка маніфесту:
  ключ джерела береться з імені розширення, шлях — зі `storagePath`;
- у **старому** дереві (до тега `legacy/gitsync-2025-02`) тека `SMB` означала *російську*
  УНФ, а `BAS small business` — *українську*. Нові назви збігаються з іменем розширення
  в Конфігураторі, тому читаються прямо.

## Структура

| Що | Де |
|---|---|
| Маніфест kit: воркспейси, джерела, `truth`, сховища | `v8storagekit.yaml` (корінь) |
| Локальне цієї машини: дев-бази `devUNF` / `devUNFru` / `devACC` | `v8storagekit.local.yaml` (гітігнорований) |
| Воркспейс Уніки: source-set-и, база агента `File=build/ib` | `<Воркспейс>/v8project.yaml` |
| Вихідники розширення | `<Воркспейс>/cfe/src` — Designer platform XML |
| Базова конфігурація вендора (`truth: vendor`) | `<Воркспейс>/cf/src` — локально, у git не потрапляє |
| Дзеркала сховищ | гілки `storage/<джерело>` — пише лише `kit sync` |
| Артефакти для людини | `build/artifacts/` (гітігноровано) |
| Мапа «користувач сховища → git-автор» | `AUTHORS` |
| Архітектура підсистеми, контракт обробки, по банках | `docs/architecture/`, `docs/banks/` |

## Гілки

`main` — історія проєкту. `storage/<джерело>` — дзеркало сховища, лише дописується.
`feature/<задача>` — гілка агента від головної; злиття дзеркала в неї — `v8storagekit:reconcile`;
PR — `v8storagekit:finish`. Реплей у головну гілку не йде.

## Наміри → скіли

| Намір | Скіл |
|---|---|
| нові версії у сховищі → git | `v8storagekit:sync` |
| вивантажити базову конфігурацію з дев-бази | `v8storagekit:dump` |
| людина перенесла частину в сховище | `v8storagekit:reconcile` |
| закрити задачу, PR | `v8storagekit:finish` |
| база агента | `v8storagekit:provision` |
| звірити git зі сховищем | `v8storagekit:verify` |
| додати воркспейс/джерело | `v8storagekit:onboarding` |

Редагування метаданих, форм, СКД, ролей; валідація; `operation=build/make/test/syntax` — Unica.

## Межі

- **Формат вихідників — Designer platform XML; платформа — гілка 8.3.27.x**
  (`C:\Program Files\1cv8\8.3.27.1644\bin\1cv8.exe`). EDT у проєкті не використовується.
- **Репозиторій публічний.** Рядки підключення, імена серверів 1С, логіни й паролі —
  лише у гітігнорованих `v8storagekit.local.yaml` і `v8project.local.yaml`.
  `File=build/ib` у `v8project.yaml` не секрет: відносний і однаковий у кожному клоні.
  Шлях сховища в маніфесті — свідомий виняток (сам собою доступу не дає).
- **`cf/src` ніколи не комітиться** — код вендора, ліцензія цього не дозволяє.
- **Сховища — тільки читання.** Жодних `ConfigurationRepositoryCommit`/`Lock`/`UnlockObjects`.
  Запис у сховище виконує людина в Конфігураторі. Гілки `storage/*` руками не редагуються —
  хук відмовить.
- **Агент працює у своїй базі й ніколи не пише в базу людини.** Базу людини kit лише читає
  (`dump`), і лише на явне прохання.
- **`-Apply` — лише на явне прохання.** `sync` і `verify` без `-Apply` усе одно піднімають
  платформу (хвилина-дві, ліцензія), але нічого не змінюють. `dump` без `-Apply` лише друкує
  базу, користувача й ціль.
- **Ліцензія 1С.** Підрядки `лиценз`, `ліценз`, `license`, `HASP` у виводі платформи — зупинка
  й доповідь; служби, реєстр, `nethasp.ini`, файли ліцензій не чіпати.
- **`git push`, `gh pr create` — лише за явним проханням.**

## Робота через Unica

**Воркспейс — тека продукту, не корінь репозиторію.** Автоскан Unica обходить усе дерево
від `cwd` і падає на першому не-UTF-8 файлі; вузький корінь заодно тримає BSL-індекс малим.

`cfe.borrow` і `cfe.diff` потребують вивантаженої `cf/src` — це `v8storagekit:dump`.
Для правок коду й форм уже запозичених об'єктів вона не обов'язкова.

Кеш Unica `.build/unica` створюється поруч із кожним використаним коренем — він у
`.gitignore` без провідного слеша, щоб ловився на всіх рівнях.

## Дозволи

`.claude/settings.json` дозволяє без запиту лише читання git і читальні інструменти Unica;
хук `SessionStart` запускає `.claude/hooks/session-start.ps1`. Команди kit — з підтвердженням:
правила дозволів працюють за префіксом, тому дозвіл на прев'ю автоматично дозволив би й той
самий рядок із `-Apply`.

## Історія до переходу на v8storagekit (межа 2025-02)

Репозиторій до лютого 2025 вивантажувався зі сховищ старим інструментом (gitsync),
і вихідники лежали в **EDT-форматі** за іншими шляхами. 2026-09-10 перехід повторено
від останньої чистої gitsync-точки: шляхи перенесено `kit rename-edt`, вміст замінено
дампом зі сховища. Тому історія **безперервна** — але деякі запити потребують прапорця.

Межа: тег `legacy/gitsync-2025-02` (коміт `dca2f8a`, 2025-02-24).

Відповідність шляхів через межу:

| Було (EDT, до межі) | Стало (Designer) |
|---|---|
| `BAS small business/src/` | `SMP_BankExchange_SMB/cfe/src/` |
| `BAS for accounting/src/` | `SMP_BankExchange_ACC/cfe/src/` |
| `SMB/src/` | `SMP_BankExchange_SMBru/cfe/src/` |
| `ExtDataProcessors/<Банк>/src/` | `epf/src/` |
| `<Об'єкт>/<Об'єкт>.mdo` | `<Об'єкт>.xml` |
| `<Об'єкт>/Forms/<Форма>/Form.form` | `<Об'єкт>/Forms/<Форма>/Ext/Form.xml` |
| `<Об'єкт>/ManagerModule.bsl` | `<Об'єкт>/Ext/ManagerModule.bsl` |
| `<Роль>/Rights.rights` | `<Роль>/Ext/Rights.xml` |

Як діставати історію:

```bash
git log --follow -- <шлях>          # ОБОВ'ЯЗКОВО --follow: без нього видно лише коміти після межі
git blame -w -- <шлях>              # -w знімає розбіжності в пробілах; для BSL працює через межу
git show legacy/gitsync-2025-02:'BAS small business/src/<шлях>'   # прочитати файл до межі
```

Перевірено на `SMP_BankExchange_SMB/.../СМП_КлиентБанк/Ext/ObjectModule.bsl`:
`--follow` дає 4 коміти проти 2 без нього, а `blame -w` приписує **2657 із 2661 рядка**
комітам 2024 року, тобто з-за межі.

Коміти конверсії перелічені в `.git-blame-ignore-revs` — увімкнути одноразово:
`git config blame.ignoreRevsFile .git-blame-ignore-revs`.
